**Streamable HTTP: a debug session another MCP client created is answered as such, not as `Session not found`** — each HTTP client session owns its own debug sessions (by design, #337/#658), but a second client naming one of them got the same `Session not found` an invalid id gets (or `Failed to close debug session`, or a protocol error from `redefine_classes`) while the program kept running under the first client. Every tool now answers `success: false` with `error: "Session <id> belongs to another MCP client session: each Streamable HTTP client sees only the debug sessions it created. It ends when that client closes its MCP session (DELETE /mcp) or when the idle reaper closes it: …"`, worded from the reaper windows actually in force (and saying so when both are `0`). The check sits in the tools/call dispatch, in front of every handler, through a lookup the HTTP layer hands each server; stdio and SSE are unchanged, and an id nobody holds keeps each tool's existing wording. `docs/tool-reference.md` now says that debug sessions are per client in HTTP mode (#939)
