**Tool failure envelopes no longer carry the `MCP error <code>:` prefix** — a `step_over`, `continue_execution`, `get_stack_trace` or any other tool that hit a session-lifecycle failure (session not found, session terminated, no active proxy) returned `{"success": false, "error": "MCP error -32600: Cannot step over: no active proxy for session …"}`, because the typed session errors extend the SDK's `McpError`, whose constructor bakes the JSON-RPC code into `.message`, and the envelope copied that verbatim — protocol plumbing that reads like a transport failure to an agent. The typed errors now keep their plain text as `detail`, which the envelopes (and `getErrorMessage`) report; the prefix remains on the JSON-RPC error path, where the SDK derives the wire error from it. `list_threads`' failure also reads `Cannot list threads: …` instead of `Cannot listThreads: …` (#647)
