**Ruby launches honour `stopOnEntry: true`** — rdbg's DAP `launch` handler releases the stop-at-load pause unconditionally on `configurationDone` (it never reads `stopOnEntry`), so a Ruby launch could not stop at entry on any platform: the script ran to completion with `stopOnEntrySuccessful: false` and no `stopped` event, contrary to the docs. Only rdbg's `attach` handler honours `nonstop`, so the launch request now goes out as an `attach` to the rdbg process mcp-debugger spawned suspended at load, with `nonstop` derived from `stopOnEntry`: `stopOnEntry: true` pauses at the first line (`state: paused`, `reason: "entry"`), and the default lets rdbg continue by itself exactly as before (#798)
