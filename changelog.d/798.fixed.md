**Ruby launches honour `stopOnEntry: true`** — rdbg's DAP `launch` handler releases the stop-at-load pause unconditionally on `configurationDone` (it never reads `stopOnEntry`), so a Ruby launch could not stop at entry on any platform: the script ran to completion with `stopOnEntrySuccessful: false` and no `stopped` event, contrary to the docs. Only rdbg's `attach` handler honours `nonstop`, so a launch that asks for an entry stop now goes out as an `attach { nonstop: false }` to the rdbg process mcp-debugger spawned suspended at load, and rdbg reports the pause as the entry stop (`state: paused`, `reason: "entry"`); a launch that does not keeps the plain `launch` request exactly as before, so nothing changes for the default path — including on debug gems older than 1.7.0, whose attach handler ignores `nonstop`. The Ruby guide and the shipped debugging skill no longer describe an entry pause that mcp-debugger "auto-continues" (rdbg releases it itself) (#798)
