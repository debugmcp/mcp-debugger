**A fresh install no longer calls the shipped JDI bridge stale** — `mcp-debugger doctor java` warned "JDI bridge source is newer than the compiled class" on every fresh `npm install` of the CLI (and of `@debugmcp/adapter-java`), and the first Java launch recompiled the bridge into the install directory, or warned on every launch where it could not write. npm extracts a package's files in tarball order, so the shipped `JdiDapServer.java` landed a few milliseconds after the shipped `.class` and the mtime comparison read that as a stale class. The build now records the source's sha256 beside the class (`java/out/jdi-bridge-build.json`) and the adapter decides by content when the record is there; an edited source still recompiles, and a class with no record (a `JDI_BRIDGE_DIR` tree, the Docker image's own `javac`) is still judged by mtime. Refs #1054.
