**A Python attach from a Windows host binds breakpoints through `pathMappings`** — debugpy was not told the client's operating system, so a Linux target assumed its own: a `C:\…\app\service.py` breakpoint matched a `localRoot` of `C:\…\app` but kept its `\` in the rest of the path (`/srv/app\service.py`, no such file on the target, "Breakpoint in file that does not exist."), and a stop reached through the target's own path came back in a mixed style (`C:\path\to\app/service.py`); a Python attach now sends `clientOS` for the machine mcp-debugger runs on (`WINDOWS` or `UNIX`) unless `adapterConfig` passes `clientOS`, `debugOptions` or `options` (#1304)
