**A Windows `pause_execution` on a launched C/C++ program now shows the program's thread, not the injected break-in thread** — CodeLLDB reports the pause on the helper thread Windows injects (an ntdll-only stack, every frame internal), while the program's own thread sits in `main` one `list_threads` away; `get_stack_trace`, `get_local_variables` and `evaluate_expression` now anchor on the first thread whose stack reaches the program and say which thread the stop was reported on in `note`. Breakpoint, step, exception and entry stops stay on the thread they were reported on, and an explicit `threadId` is always shown as asked (#898)
