**Every PAUSED arrival answer now carries a bounded `snapshot` — exception, top frames, locals — so reading crash state costs zero extra tool calls** — `start_debugging`, `restart_debugging`, `wait_for_stop`, `pause_execution`, `attach_to_process` and the `create_debug_session` attach shortcut answer a stop with `snapshot: { exception?, frames, locals?, truncation?, note? }`, composed from the landing read's own stack (never a second resolve): the exception from the stop record (secret-redacted; DAP `exceptionInfo` included only if already merged, never awaited), the top ≤3 policy-filtered frames, and the top frame's locals through the `get_local_variables` pipeline under tight caps (20 locals / 200 chars, `DEBUG_MCP_SNAPSHOT_MAX_LOCALS` / `DEBUG_MCP_SNAPSHOT_MAX_VALUE_CHARS`) and a 2 s bound whose note says what expired. `DEBUG_MCP_NO_SNAPSHOT=1` turns it off; `DEBUG_MCP_VARIABLE_ACCESS=explicit` withholds the locals half; entry stops, dry runs and `pending` answers carry none. Attach answers gain landing parity (`location`/`threadId`/`context` beside the note), and the raw `lastStop` emissions (`wait_for_stop`, `get_stack_trace`, `list_debug_sessions`) are now secret-redacted copies (#982)
