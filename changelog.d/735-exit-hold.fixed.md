**A worker whose exit is still being held for its IPC drain is reported as running, as the session is** — while the proxy wrapper held a worker's raw exit back for the channel to drain (the #729 fix, up to 1 s), its public exit fields were already set, so `ProxyManager.isRunning()` answered false against a session still shown running or paused: a tool call landing in that window failed with "no active proxy", `list_debug_sessions` dropped the session's `exposure`, and `stop()` resolved without waiting for the exit. The wrapper now writes `exitCode`/`signalCode` when it delivers the `exit` event, keeps refusing writes and kills on the raw exit it has already seen, and the manager's one-`exit`-per-worker latch is reset when a worker is spawned rather than in cleanup, so a closure status followed by a held exit delivered after `stop()` no longer emits `exit` twice (#735)
