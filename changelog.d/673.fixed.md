**Breakpoints that fire are reported bound** — on a JavaScript launch session, `list_breakpoints` kept reporting `verified: false, message: "Unbound breakpoint"` for breakpoints the debuggee had demonstrably stopped on: js-debug verifies a source-mapped `src/x.ts` request under its *generated* `dist/x.js` path and line, which matched nothing in the store, and sends no verification at all for a `node_modules` file. The session now remembers the child session's provisional breakpoint ids (never as a trusted `adapterId`, and never for the parent's colliding id space, #495), so the later verification under a generated location binds the right record — reported as `boundFile`/`boundLine` beside the untouched request — and a `stopped` event's `hitBreakpointIds` marks the breakpoints it names verified for every adapter, dropping the stale unbound message. Upgrade-only: nothing here can downgrade a verified breakpoint (#673)
