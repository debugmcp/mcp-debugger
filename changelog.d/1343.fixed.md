**`close_debug_session` on a child session of an attached tree releases the child instead of ending it** — a Python target started with `python -m debugpy --listen` reports the processes it starts, which become child sessions, and closing one of those by name sent its connection `disconnect { terminateDebuggee: true }` and answered `processEnded: true`: the server ended a process it had not started, and the target saw its child exit 0 as if it had finished its work (measured: the child never printed its last line). Whether a close ends or releases a process is now read from how its tree was started, which every session of the tree shares, for a named child and the children below it as well as for a root: in an attached tree the child and its descendants are disconnected with `terminateDebuggee: false`, run on undebugged, and the answer says `released: true`, as closing the root already did. The same holds when an adoption fails and the server closes the child it gave up on. Launched trees are unchanged (closing a Python child of a launched tree still ends it), and ending the processes of an attached tree still takes `detach_from_process { terminateProcess: true }` on its root. A child's `released` states the release the close asked for; the debug adapter's answer to it is not yet read back (#1350) (#1343)
