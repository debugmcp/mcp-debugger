**`adapter-configured` (with `init-received` and `dry-run-complete`) fired every listener twice per status message** — every worker status ran through both ProxyManager's imperative handler and the functional core, and both emitted the event; only idempotent listeners kept it harmless, and since #704 the JavaScript launch takes this path on every child adoption. The functional core now returns state transitions for status messages and nothing else — no log, no event, no kill — so the imperative handler that owns their latches is the single emitter, statuses are logged once instead of twice, and the IPC probe kills the proxy once instead of twice (#713)
