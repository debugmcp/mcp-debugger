**A second MCP conformance lane for the 2026-07-28 revision, judged by the suite itself.** `node scripts/mcp-conformance.mjs --era 2026-07-28` runs the protocol org's conformance suite on its 0.2 line (`@modelcontextprotocol/conformance@0.2.0-alpha.12`, the line the SDKs run) with `--requirements 2026-07-28` — everything the revision requires of a server — against a local `http` server, and hands the suite its own baseline with `--expected-failures`: the suite fails the run on a failure or warning that is not listed and on a listed entry that passes, and its exit code is the lane's verdict. `scripts/conformance/expected-failures-2026-07-28.yaml` lists what cannot be tested against this server — 18 scenarios and checks that only drive the suite's reference fixtures (the "everything server" tools, resources and prompts), and 13 that need an optional feature this server does not declare (`completions`, input-required results) — each with the fixture or feature named beside it; none is a protocol divergence, and by the suite's own policy a missing prerequisite is a failure, not a skip (upstream discussion: modelcontextprotocol/conformance#516). CI runs it as `mcp-conformance-2026`, required in the test summary beside the 2025-11-25 lane, which is unchanged. Running the suite found two real gaps, both fixed in both eras: `resources/templates/list` answered "Method not found" (a server advertising the resources capability must answer it; it now answers an empty list), and the error for an unknown resource carried no `data` (it now names the requested `uri`, SEP-2164).
