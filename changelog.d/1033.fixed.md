**`wait_for_stop` reports the breakpoints a program ran past when it ends after the launch hold** — the "verified but never hit" summary and `unhitBreakpoints` (#701) were only on the `start_debugging` answer, so a program that outlived the 1 s hold got a `pending` launch answer and then a bare "ran to completion" from the `wait_for_stop` that reported its exit: the same program answered differently depending on where it ended. The terminal `wait_for_stop` answer now carries the same summary when no stop was recorded in the launch — the sentence names the verified breakpoints and `unhitBreakpoints` lists every line breakpoint the program never reached; a program resumed past a stop keeps the plain exit message (#1033)
