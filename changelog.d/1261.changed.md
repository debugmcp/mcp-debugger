**An attach by processId closes the Node.js inspector it opened when its session ends** — `attach_to_process { processId }` makes Node open its inspector (on `127.0.0.1:9229` unless the target set `--inspect-port`), and it used to stay listening after `detach_from_process` and `close_debug_session`: a later attach by `port: 9229` reused it, and while it held the port an attach by processId to any other Node process on the host was refused. Once js-debug has disconnected, the session that opened it now closes it — on detach, on close, after an attach that failed, when the session's connection ends by itself, and when the server shuts down — and the process runs on. An inspector that was already open (a target started with `--inspect`, or one another tool left open) is left open, and of several sessions of this server on one inspector it opened, the last to leave closes it; attaches and closes on one endpoint run one at a time, so a session that joins it is never cut off by another's close. Every JavaScript attach, detach and close answer says which in one field, `inspector` (`opened by this attach …`, `closed: …`, `left open: …`, or `not confirmed closed: …` with the reason when the close could not be confirmed). To attach again, attach by processId again: the signal opens the inspector again; an attach by `port` to an inspector a closed session opened now finds nothing listening. A client from outside the server attached to that inspector is dropped by the close. One attach has one endpoint — the `port` passed, else the port of an inspector this server already holds for that process (looked at only: no signal is sent for it), else `127.0.0.1:9229` — and the server closes only an inspector it opened and identified there: a target started with `--inspect-port=<n>` and attached by processId without `port: <n>` still fails, now saying that the signal was sent and that nothing was closed, and the inspector the signal opened stays open until the target restarts (#1310). A session that a new launch or attach replaces keeps the report of what its previous run gave back until a detach, close or failed attach carries it (#1261)
