**An attach by processId closes the Node.js inspector it opened when its session ends** — `attach_to_process { processId }` makes Node open its inspector (on `127.0.0.1:9229` unless the target set `--inspect-port`), and it used to stay listening after `detach_from_process` and `close_debug_session`: a later attach by `port: 9229` reused it, and while it held the port an attach by processId to any other Node process on the host was refused. Once js-debug has disconnected, the session that opened it now closes it — on detach, on close, after an attach that failed, and when the server shuts down — and the process runs on. An inspector that was already open (a target started with `--inspect`, or one another tool left open) is left open, and of several sessions of this server on one inspector it opened, the last to leave closes it. Every JavaScript attach, detach and close answer says which in one field, `inspector` (`opened by this attach …`, `closed: …`, `left open: …`, or `not confirmed closed: …` when the close could not be confirmed). To attach again, attach by processId again: the signal opens the inspector again; an attach by `port` to an inspector a closed session opened now finds nothing listening. A client from outside the server attached to that inspector is dropped by the close (#1261)
