**The server's `instructions` fit in what Claude Code shows the model** — they were 6,536 characters, and Claude Code puts only the first 4,096 in front of the model (measured on 2026-11-28 in the first model request of agent trials against 0.27.0), so the attach, logpoint, restart and output rules, the pointer to the `debugging-workflow` prompt and the skill, and the rules an operator's setting adds (the idle policy, least-privilege variable access) never arrived. The instructions are now at most 4,096 characters for every value of the settings they depend on (3,556 by default; a unit test holds the bound), ASCII, and ordered by what an agent needs before its first call: the rules an operator's setting adds, then the shortest path for a launch, a failing test and an attach, what a stop answer may already carry, waiting, logpoints, how a session ends, and where the rest is. Rules about one tool moved into that tool's description, each long one stated once: what a stop's `snapshot` may carry and the `changedVariables` shapes in `wait_for_stop` (the step tools and `pause_execution` point to it); the redaction rule in `get_variables` (`get_local_variables`, `evaluate_expression` and `get_output` point to it); the attach start forms, path mappings and the Kubernetes guide in `attach_to_process`; the moved-breakpoint answer and late verification in `set_breakpoint`; the IDE configuration in `expose_session`; what a close asks of the program in `close_debug_session`. Sentences that promised what the runtime does not guarantee now say what is requested and where the answer says what happened: a close, a detach or an idle expiry asks for an attached program to be released (a close or detach answer's `released`, `processEnded` or `warning` says what became of it); an attach requests a pause unless `stopOnEntry` is false or the target has not answered its breakpoints; the idle policy's exemption for an open notification stream holds over HTTP only; a snapshot, its locals, the exception's type and message and the diff are what an answer may carry; an attach applies no default exception filter; a Java breakpoint may name a class instead of a path; the `DEBUG_MCP_NO_REDACT` and `DEBUG_MCP_NO_SNAPSHOT` descriptions name `true` as well as `1`, and changing redaction takes a restart; and a passing pytest test is no longer promised to run to completion (issue #1333: the preset can pause at an exception the test handles, such as one raised in a dataclass's `__post_init__` inside `pytest.raises`; `continue_execution` goes on, `breakOnExceptions: "none"` turns the stops off). Rules that were not true in every configuration now are: paths are project-relative in container mode (the text said absolute), a server with `DEBUG_MCP_NO_SNAPSHOT` or `DEBUG_MCP_VARIABLE_ACCESS=explicit` no longer promises snapshot locals, function breakpoints are no longer suggested where `DEBUG_MCP_BP_ADDRESSING` disables them, a pytest launch is no longer promised a paused answer (it can answer `pending: true`), and a C/C++ program on Windows is no longer promised a stop at an uncaught exception (#1331)
