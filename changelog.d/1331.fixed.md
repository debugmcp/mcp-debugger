**The server's `instructions` fit in what Claude Code shows the model** — they were 6,536 characters, and Claude Code puts only the first 4,096 in front of the model (measured on 2026-11-28 in the first model request of agent trials against 0.27.0), so the attach, logpoint, restart and output rules, the pointer to the `debugging-workflow` prompt and the skill, and the rules an operator's setting adds (the idle policy, least-privilege variable access) never arrived. The instructions are now at most 4,096 characters in every configuration (3,385 by default; a unit test holds the bound), ASCII, and ordered by what an agent needs before its first call: the rules an operator's setting adds, then the shortest path for a launch, a failing test and an attach, what a stop answer already carries, waiting, logpoints, how a session ends, and where the rest is. Rules about one tool moved into that tool's description: the `changedVariables` shapes into the step tools, `pause_execution` and `wait_for_stop`; the attach start forms, path mappings and the Kubernetes guide into `attach_to_process`; the redaction placeholders into `get_variables`, `get_local_variables`, `evaluate_expression` and `get_output`; the moved-breakpoint answer and late verification into `set_breakpoint`; the IDE configuration into `expose_session`; what a close does to the program into `close_debug_session`. Rules that were not true in every configuration now are: paths are project-relative in container mode (the text said absolute), a server with `DEBUG_MCP_NO_SNAPSHOT=1` or `DEBUG_MCP_VARIABLE_ACCESS=explicit` no longer promises snapshot locals, function breakpoints are no longer suggested where `DEBUG_MCP_BP_ADDRESSING` disables them, a pytest launch is no longer promised a paused answer (it can answer `pending: true`), and a C/C++ program on Windows is no longer promised a stop at an uncaught exception (#1331)
