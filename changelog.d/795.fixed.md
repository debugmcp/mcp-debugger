**An adapter whose import fails is no longer reported as "Adapter not installed"** — a missing transitive dependency (measured: `dotenv` absent next to an installed `@debugmcp/adapter-javascript`) raised the same module-not-found code as an absent package, so the loader said `Adapter not installed. Install with: npm install @debugmcp/adapter-javascript`, discarded the import's own error while trying its fallback paths, and `start_debugging` then answered `No debug adapter registered for language: javascript. Available: … javascript …` — the language listed as available in its own failure, `dotenv` never named. The loader now keeps the primary import's error, asks the package resolver whether the package is on disk before calling it "not installed", and otherwise says `The package is installed but importing it failed: Cannot find package 'dotenv' imported from … — its dependency 'dotenv' is missing or broken`; that reason travels as the `cause` of the registry's error, whose message now reads `No debug adapter could be loaded for language: javascript — …` with the failed language left out of `Available`; and `list_supported_languages` carries a per-language `warning` with the same words (the modes stay advisory) (#795)
