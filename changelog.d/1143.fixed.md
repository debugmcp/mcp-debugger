**Python frame names are the functions' names at a pytest exception stop.** pydevd marks the frame execution is paused in by appending ` (Current frame)` to its name, and that suffix reached `get_stack_trace`, `snapshot.frames` and the frame of `get_local_variables`, where it broke anything that compares a frame name with a function name. The marker is gone. What it said is data now: the frames the exception has already left, which pydevd lists above the live one, carry `unwound: true`, so the first frame without the flag is where the program is paused, and the answer's `note` says both (`The exception was raised in 'check_positive', which has already unwound: its variables are readable. Execution is paused in 'test_assert_in_helper' (test_billing.py:20); a step continues from there.`). A stop whose frame 0 is live carries no flag and no such note. (#1143)
