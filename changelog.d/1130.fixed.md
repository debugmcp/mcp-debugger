**A JavaScript step lands where your code next runs, and is no longer lost in Node's own code.** `step_into` on a line that calls a Node builtin took about 6 s on a Linux host and answered `pending`, blaming "a long-running call"; on the first `console.log` of a process it never landed at all and the program ran to its end. js-debug's own "smart stepper" was deciding where such a step ends: while the step was in skipped code it stepped again by itself, one engine step per statement (131 for one `console.log`), with a flag that moves the step to a later task and loses it. That stepper is now off for every session, and the server steps through skipped code itself, over js-debug's raw CDP socket, for `step_into`, `step_over` and `step_out` alike. A `step_into` on a line that calls your own function through skipped code (an event listener behind `emitter.emit`, an array callback, a route handler from inside express) lands in that function; on a line whose call stays in skipped code for the whole walk (`console.log`, a `require`) it lands on the next line and the message says how far the walk went (`Stepped into. step_into walked 25 engine steps into the call on that line and was still in skipped code …`) and that code of yours the call reaches further in ran without stopping; on a line that only starts a later task (`setTimeout`) it lands on the next line instead of inside the callback some time later. A `step_over` or `step_out` that returns into skipped code steps out to the nearest frame of your program below; when nothing of your program called or awaits the function (the last line of a request handler, a timer callback, a `.then` callback) the program is resumed rather than walked through the internals of later tasks, and the pending answer says the step left its frame. What counts as skipped is still js-debug's own verdict, so `justMyCode`, your `skipFiles` and source maps decide it as before, and `justMyCode: false` (or `smartStep: false`) still lands every step where V8 lands. A forked child steps the way its root session does, launched or attached. Changed on purpose: a pause asked for while a step is still pending is reported as the pause, where the program is, and is not stepped away from; and the sentence a pending step carries no longer mentions js-debug's stepper. On Linux every engine step costs about 46 ms whoever sends it (#1163), so a `step_into` on a `console.log` line still takes over a second there. (#1130)
