**A JavaScript step lands where your code next runs, and is no longer lost in Node's own code.** `step_into` on a line that calls a Node builtin took about 6 s on a Linux host and answered `pending`, blaming "a long-running call"; on the first `console.log` of a process it never landed at all and the program ran to its end. js-debug's own "smart stepper" was deciding where such a step ends: while the step was in skipped code it stepped again by itself, one engine step per statement (131 for one `console.log`), with a flag that moves the step to a later task and loses it. That stepper is now off for every session, and the server steps through skipped code itself, over js-debug's raw CDP socket, for `step_into`, `step_over` and `step_out` alike. A `step_into` on a line that calls your own function through skipped code (an event listener behind `emitter.emit`, an array callback, a route handler from inside express) lands in that function; on a line that calls only skipped code it lands on the next line and the message says so (`Stepped into. The call on that line ran only skipped code …`); on a line that only starts a later task (`setTimeout`) it lands on the next line instead of inside the callback some time later. A `step_over` or `step_out` that returns into skipped code steps out to the nearest frame of your program below; when there is none (the last line of a request handler or a timer callback) the program is resumed rather than walked through the internals of later tasks, and the pending answer says the step left its frame. What counts as skipped is still js-debug's own verdict, so `justMyCode`, your `skipFiles` and source maps behave as before, and `justMyCode: false` (or `smartStep: false`) still lands every step where V8 lands. A forked child steps the same way. Changed on purpose: a `debugger;` statement or a pause in a dependency now stops there instead of being stepped away from, and the sentence a pending step carries no longer mentions js-debug's stepper. On Linux every engine step costs about 46 ms whoever sends it, so a `step_into` on a `console.log` line still takes over a second there. (#1130)
