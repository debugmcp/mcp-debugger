**A `set_breakpoint` refusal no longer suggests a `statement` that cannot be found.** When `expectedContent` did not match the line, the refusal ended "Or address by content: set_breakpoint {statement: "<the expected text>"}" whatever that text was — including text that is nowhere in the file, where following the hint answered `statement … not found`. The sentence is now the statement resolver's own answer for the expected text, so the two cannot disagree: on one line it names it ("…that text is on line 11."); on several it adds `nearLine` and lists the lines; and when the resolver would not find it — the text is absent, or it is only in a comment or past a `//` or `#`, where statement matching does not look — no statement is offered and the refusal names the lines the same `expectedContent` would pass on ("That expectedContent matches line 12."), or says "That expectedContent matches no line of the file." An expectation that spans lines gets no such sentence. (#1142)
