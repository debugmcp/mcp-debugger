**A `set_breakpoint` refusal no longer suggests a `statement` that cannot be found.** When `expectedContent` did not match the line, the refusal ended "Or address by content: set_breakpoint {statement: "<the expected text>"}" whatever that text was — including text that is nowhere in the file, where following the hint answered `statement … not found`. The sentence is now the statement resolver's own answer for the expected text, so the two cannot disagree: on one line it names it ("…that text is on line 11."); on several it adds `nearLine` and lists the lines; on none it says "That text matches no line of the file, so it cannot be addressed by content (statement) either."; and an expectation that is a comment, a blank or spans lines gets no such sentence.
