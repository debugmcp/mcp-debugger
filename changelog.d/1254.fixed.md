**Non-zero exit answers now include `outputTail` and top-level `exitCode`/`unhitBreakpoints`** — when a launched program ended with a non-zero exit code before hitting any breakpoint (for example `No module named pytest` or a runner finding no test files), `start_debugging`, `restart_debugging`, `wait_for_stop` and `step_*` reported only the exit code, requiring an extra `get_output` call to see why it exited, and `start_debugging`/`restart_debugging` nested `exitCode` and `unhitBreakpoints` inside `data` only. Every answer reporting a run's end with a non-zero exit code and captured output now carries `outputTail` (the last lines of the session's captured output — up to 8 non-empty lines, 300 characters per line, sharing `outputBeforeFailure`'s bounds) with a short `get_output` pointer in `message`, and `start_debugging`/`restart_debugging` hoist `exitCode`, `unhitBreakpoints` and `outputTail` to the top level through the same shared helper as `wait_for_stop` and `step_*` (omitting the duplicate `outputTail` from `data`) (#1254, #1136)
