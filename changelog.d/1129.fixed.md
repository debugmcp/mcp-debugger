**The server's own idle-policy settings are no longer displayed as redacted secrets.** The environment sanitizer masked any variable whose name contained `session` followed by `id`, and `SESSION_IDLE` contains `SESSION_ID`: the dev proxy's `dev_server_status` showed `MCP_DEBUG_SESSION_IDLE_MS` and `MCP_DEBUG_SESSION_IDLE_SWEEP_MS` as `[REDACTED]`, so an operator could not read back which idle window was in force. The rule now reads the word after `session` to its end: `SESSION_ID`, `sessionIds`, `SessionIDValue`, `SESSION_IDENTIFIER` and run-on spellings such as `JSESSIONID` are still masked; a name where `id` only begins a longer word (`SESSION_IDLE`, `sessionIdx`) is shown. `session.id` and `SESSION ID`, with a separator the old pattern did not know, are now masked too.
