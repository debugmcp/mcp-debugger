**Closing a `flutter run` session stops the desktop app** — on Windows `close_debug_session` (and `restart_debugging`) left the app running after every close, four `flutter_probe.exe` after four sessions, with the tool's `dart development-service` beside it: the Flutter SDK's debug adapter treats DAP `disconnect` as the forced path and SIGKILLs only its own tool processes, and only a DAP `terminate` tells the tool to stop the app. mcp-debugger never sent one. The proxy worker now sends `terminate` ahead of the `disconnect` for adapters whose policy asks for it (the Dart and Flutter SDK adapters, `terminateBeforeDisconnect`), when the adapter advertised `supportsTerminateRequest` and the program has not already ended, waits up to 2 s for the answer and then disconnects as before; the Flutter desktop smoke and the Dart logpoint smoke now assert on the process table that the program is gone within 5 s of the close (#885)
