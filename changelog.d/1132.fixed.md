**Pausing a Dart program that is idle in an `await` answers at once and says what it is.** `pause_execution` on a Dart isolate waiting between events took 3 s to answer `paused` with an empty stack, said the target `may be paused in native code`, and suggested another thread or pausing again, neither of which can work: the program has one thread, and it idles in the same `await` the next time too. The Dart policy now says what an empty paused stack means there (`The isolate is idle between events (waiting in an `await`), so no Dart frame is on its stack; ... set a breakpoint in the code that runs next ... and continue_execution`), and the answer comes in tens of milliseconds, because an empty first stack read is an idle isolate (measured, ten pauses each, idle against busy). `get_local_variables` on such a stop carries the same sentence, where it used to add the generic remedy the sentence refutes. Other adapters keep the readiness wait, which exists for stacks that have not materialised yet, and so does a Dart stop that is not a pause. (#1132)
