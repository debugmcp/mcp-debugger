**COBOL: the synthesised PERFORM frame names the performer from the manifest's call site** — at a stop inside a performed paragraph the frame under it read `1000-INIT (PERFORM 1000-INIT)` at the paragraph's own inline PERFORM (GnuCOBOL 3.1.2) or was missing altogether (the Linux 3.2 image), because the PERFORM line came from the entry's return address through the engine's line table, which attributes that address three ways across compilers. The shim now takes the PERFORM statement from the control flow the manifest already records — the call site whose THRU label is the entry's `perform_through`, with the line table only to tell apart several PERFORMs of one range, or as the fallback for a manifest without call sites — so the frame reads `0000-MAIN (PERFORM 1000-INIT)` at the PERFORM statement on every compiler; `step_out`'s PERFORM line comes from the same reading. Docs: the `MCP_COBOL_ALLOW_PREBUILT` variable was documented but never read — a prebuilt COBOL executable launches without cobc as it always did (#1034)
