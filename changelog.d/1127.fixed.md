**The idle policy no longer closes a session underneath its own call.** With `MCP_DEBUG_SESSION_IDLE_MS` set, a tool call counted as activity only at the moment it was dispatched, so a call that ran longer than the window — a launch that builds first, a slow launch on a busy host, an `attach_to_process` with a long `verifyTimeout` — had its session closed while it was still in flight and answered a generic launch failure. Every tool call that names a session now holds that session's tree for as long as it runs (the hold was `wait_for_stop`'s alone), and the idle clock starts over when the call answers, so a slow call no longer uses up the window it was made in. `list_debug_sessions` shows `idleMs: 0` for a session with a call in flight, and a call that arrives while the policy is closing a session waits for that close and answers `closedBy: "idle-policy"`.
