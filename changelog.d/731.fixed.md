**JavaScript sessions on a nested mcp-debugger report `exitCode` again** — a server that is itself a js-debug debuggee inherits the outer session's exit-code shim env (`NODE_OPTIONS --require .../exitcode-shim.cjs`, `MCP_DEBUGGER_EXITCODE_FILE`, `MCP_DEBUGGER_EXITCODE_CLAIMED=1`), and its JavaScript adapter treated the inherited preload as its own, so inner debuggees inherited the claim, registered no exit handler and ended "without reporting an exit code"; the adapter now scrubs the inherited triplet (by upper-cased key, removing only its own `--require` token and leaving every other `NODE_OPTIONS` token — and their internal whitespace — untouched) from the debuggee and adapter-process env and stamps a fresh file, hands the debuggee an explicit empty claim, and no longer risks reading the outer session's exit-code file when its own shim asset is missing. The scrub runs before a caller's `dapLaunchArgs.env` is overlaid, so a caller-supplied `MCP_DEBUGGER_EXITCODE_CLAIMED: "1"` still opts the debuggee out; and the shim now consumes `MCP_DEBUGGER_EXITCODE_FILE` once it claims it, so no descendant can write the root's exit-code file even if the claim is cleared further down the tree (#731)
