**JavaScript sessions on a nested mcp-debugger report `exitCode` again** — a server that is itself a js-debug debuggee inherits the outer session's exit-code shim env (`NODE_OPTIONS --require .../exitcode-shim.cjs`, `MCP_DEBUGGER_EXITCODE_FILE`, `MCP_DEBUGGER_EXITCODE_CLAIMED=1`), and its JavaScript adapter treated the inherited preload as its own, so inner debuggees inherited the claim, registered no exit handler and ended "without reporting an exit code"; the adapter now scrubs the inherited triplet (by upper-cased key, keeping every other `NODE_OPTIONS` token) from the debuggee and adapter-process env and stamps a fresh file, hands the debuggee an explicit empty claim so js-debug's env overlay cannot resurrect the outer one, and no longer risks reading the outer session's exit-code file when its own shim asset is missing (#731)
