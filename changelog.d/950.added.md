**The stale-build warning now covers the compiled languages' prebuilt paths** — Java and .NET never compile user code (JDI binds through the `.class`, netcoredbg through the DLL's PDB), and a Go `exec`, Rust binary / `cargo`, C/C++ or COBOL prebuilt launch runs the executable as given, so a source newer than its artefact used to put the echoed line on a different statement than the one that runs, with no signal. Once `start_debugging` has named the artefact — the `.class` under a `classpath` directory at the source's package path or beside the source, the launched DLL, the executable the launch runs (C/C++ headers and COBOL copybooks included) — a `set_breakpoint` in a newer source adds the hedged `warning` naming both files and their mtimes, and `step_*`, `wait_for_stop` and `pause_execution` carry it as a `note`. `AdapterPolicy.generatedFileCandidates` now receives the transformed launch (`program`, `launchConfig`) and answers candidates tagged `linkedBy: 'sourceMap' | 'launch'`; the core's js-debug-shaped exemption moved into the JS policy (#950)
