**Attach addressing contract** — each adapter now declares on its factory metadata (`modes.attachBy`) which `attach_to_process` addressing forms it accepts (`processId`, `port`, a debugger URI under `adapterConfig`), and the core refuses any other form by name before the session changes state: a `processId` on a port-only language (Python, Ruby, Java, Dart) answers with the adapter's own recipe for opening a port, a `port` or a remote `host` on a PID-only language (C/C++, COBOL, .NET) says so, and a request naming neither on a language whose forms are those two is refused as "needs port" / "needs processId" instead of failing later with the debugger's defaults. The session stays usable after a refusal, and `list_supported_languages` shows the forms as `modes.attach.by`. Previously the top-level keys reached each adapter's transform, which dropped what it did not use silently — the class behind #450, #466, #871 and #895. The `processId` an adapter consumes (C/C++, COBOL, JavaScript) is no longer reported as an ignored `adapterConfig` key (#903)
