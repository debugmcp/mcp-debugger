**A CodeLLDB attach's initial stop is reported as a pause, not an exception** — on Windows, attaching to a process by PID (C/C++ and COBOL) reported the target's post-attach stop as `lastStop.reason: "exception"` / `stopReason: "exception"` with `Exception 0x80000003 encountered at address …`: that is the `DebugBreakProcess` break-in Windows injects to stop the target for the attach, on a helper thread, and nothing in the program threw. CodeLLDB stops the target itself when the attach did not opt out of `stopOnEntry`, so the session layer never armed the pause intent the shared normalizer keyed on; the first stop of such an attach is now `pause`, with the adapter's own reason kept as `rawReason: "exception"` and its description beside it. The stop-reason context's `stopOnEntry` now reads an attach the way the attach controller and the adapters do — stop unless told not to — so a real `__debugbreak()` met first by an attach that passed `stopOnEntry: false` stays an exception (#817)
