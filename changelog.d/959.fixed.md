A .NET launch whose program is a `.cs`, `.fs` or `.vb` source file, which is what happens when `dapLaunchArgs.program` is left out, is now refused before netcoredbg starts. The answer says the program must be the compiled assembly, names `dapLaunchArgs.program` and the `bin/Debug/<framework>/<Project>.dll` convention, and names the built DLL when the project has exactly one. The same answer comes back from `dryRunSpawn`. Before this, the launch reached netcoredbg and failed at `configurationDone` with a bare `0x800700c1`. When netcoredbg does answer with that code, for a native executable or an unmanaged or wrong-architecture DLL, the error now adds a sentence saying netcoredbg could not start the program as a .NET assembly (#959)
