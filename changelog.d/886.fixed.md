**The release dry-run fails on a package that has never been published** — `scripts/release-dry-run.sh` asked npm only whether each package's *version* already existed, and a package that had never been published returned the same 404 as a not-yet-released version, so the check passed silently; the next tag would then have failed its first OIDC `npm publish` mid-run, after the earlier packages had gone out. The loop now asks for the package by name first: a 404 on the bare name fails the dry-run with the first-time-package steps from `docs/release-checklist.md`, a non-404 registry error stays a warning, and the already-published-version warning follows as before (#886)
