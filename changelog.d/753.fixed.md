**Go launches report the program's exit code** — Delve never sends a DAP `exited` event and states the status only as a console line, `Process N has exited with status S`, so a Go run left `exitCode` empty in `list_debug_sessions` and the `start_debugging` summary said the program "ended without reporting an exit code" where python, JavaScript and C/C++ said `exit code 0` for the same program, in debug mode and under `noDebug` alike. The Go policy now reads that line back and the proxy replays it as `exited` ahead of `terminated`, the way the js-debug shim's recorded code (#247) and rdbg's process status (#258) already are. The ordering was the crux: under `noDebug` Delve prints the line before `terminated`, but in debug mode only in reply to `disconnect` — which the proxy used to send after `terminated`, once the session had stopped listening — so for an adapter that reports this way the proxy now sends the disconnect first, reads the line, and only then forwards `terminated` (bounded by the existing 1 s disconnect cap; no line means no code). Side effect: the status line and Delve's `Detaching` now reach `get_output` in debug mode too (#753)
