**A JavaScript step that leaves a function through `return` inside `try … finally` lands in the caller.** V8 never pauses for such a step (measured on V8 12.4, 13.6 and 14.6 with a bare CDP client): a `step_out` of the function, a `step_over` off its `finally` block, and a `step_out` of an `async` function with that shape all answered `Step completed as session exited.` while the program ran on. Node's own module loader returns that way too, which is how a `step_into` on a `require` line was lost. A step no longer counts on V8 alone to come back to a frame: before it can leave one that way, the server sets temporary breakpoints on the frame the step returns to (the nearest frame of your program below, or the awaiting function of an `async` one), and whichever pauses first is the landing. That is something the server does in your process: at most 24 temporary breakpoints, for the length of one step (every `step_out`; a `step_over` or `step_into` in a function whose text contains `finally`; a step that walks through skipped code), removed when the step ends however it ends. A function that returns to itself gets none for `step_over` and `step_into`. Not covered: a `step_over` across the first load of a module that has a breakpoint in it still runs on (#1162). (#1161)
