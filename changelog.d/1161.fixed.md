**A JavaScript step out of a function that returns inside `try … finally` lands in the caller.** V8 loses such a step (measured on V8 12.4, 13.6 and 14.6 with a bare CDP client; also a `return` out of a `for … of` loop and out of a function with a `using` declaration): a `step_out` of the function and a `step_over` off its `finally` block answered `Step completed as session exited.` while the program ran on. Node's own module loader returns that way too, which is how a `step_into` on a `require` line was lost. The server now sets temporary breakpoints on the frame such a step returns to, and whichever pauses first is the landing. That is something the server does in your process: at most 24 temporary breakpoints per guarded frame, for the length of one step, removed when the step ends however it ends. They are set only where a hit proves the step came back: the function being left is a plain one (not `async`, not a generator), and the frame it returns to stays on the stack until it reaches one. A step V8 loses in an `async` function or a generator is not rescued: a breakpoint below a function that can suspend cannot tell it returning from it pausing at an `await`, so that step stays lost as before and its pending answer says so (#1174). Not covered either: a `step_over` across the first load of a module that has a breakpoint in it (#1162). (#1161)
