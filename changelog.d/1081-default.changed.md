**Python child processes are debugged by default** — a Python launch now sends debugpy `subProcess: true` unless `dapLaunchArgs.subProcess` says otherwise, so every Python child the program starts (`subprocess`, `multiprocessing`, pytest-xdist workers, an autoreloader) is reported and becomes a child debug session: listed with `parentSessionId`, stopping on the parent's breakpoints, reported by the parent's `wait_for_stop` with `sessionId` naming it. Each child parks until it is adopted (about 110 ms) and counts against `DEBUG_MCP_MAX_CHILD_SESSIONS` (default 32). Opt out per launch with `dapLaunchArgs: { subProcess: false }` (the children run undebugged, as before; the answer's warning says so) or server-wide with `DEBUG_MCP_MAX_CHILD_SESSIONS=0`. A by-port attach target decides for itself at listen time (`python -m debugpy --listen … --configure-subProcess false` keeps its children undebugged): the attach request's `subProcess` is forwarded for the record, and an explicit `false` gets a note saying so (#1005, #1081).
