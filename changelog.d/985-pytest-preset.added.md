**One-call failing-test debugging for Python: `start_debugging { scriptPath: <test file>, testRunner: "pytest", testTarget: "test_name" }`** — no breakpoint needed. The preset runs `python -m pytest <file>[::<target>] -x` from pytest's rootdir (pytest's own rule: the nearest ancestor of the file holding `pytest.ini`, a `pyproject.toml` with a `[tool.pytest.ini_options]` table, a `tox.ini` with `[pytest]` or a `setup.cfg` with `[tool:pytest]`, else `setup.py`; then the top-most `conftest.py` ancestor; `dapLaunchArgs.cwd` overrides it), with pytest-xdist and pytest-cov turned off — `-p no:<plugin>`, or the plugin's inert switch (`-n0` / `--no-cov`) when the project's own `addopts` turns it on, so its options still parse — and arms debugpy's `userUnhandled` filter beside `uncaught` under the `breakOnExceptions` default — pytest catches every test failure, so `uncaught` alone never fired on one. The launch answer is the autopsy: paused at the failing assert, or at the raise site of an exception that escapes the test (the helper frame first, the live test frame below it), with `snapshot.exception`, `snapshot.frames` and `snapshot.locals`; a passing test runs to completion with exit code 0. `testTarget` is `test_name`, `Class::test_name`, `test_name[param]` or a node id of that file (one naming another file is refused); your `args` are appended as pytest arguments, and a plugin they ask for is left alone. Which runners a language takes is declared on its factory metadata (`modes.testRunners`, shown by `list_supported_languages`) and gated before the session changes state, so `testRunner: "jest"` on a Python session is refused by name with the runners Python does take. The preset rides in `adapterLaunchConfig`, so `restart_debugging` replays it and a dry run reports `data.script: "module: pytest"`. pydevd's `(note: full exception trace is shown but execution is paused at: …)` suffix no longer leaks into `snapshot.exception.type`. Measured shapes — `pytest.raises` never pauses, `pytest.skip()` pauses once, a `print` before the assert reaches `get_output` with pytest's report after the run — are in `docs/python/spike-notes-pytest.md`. Any `dapLaunchArgs: { module: "pytest" }` launch gets the same exception filters (#985)
