**The launch's `pending` answer names what is armed when it answers, not when it began** — `start_debugging` read the session's breakpoints once, before waiting, to choose between a 30 s and a 5 s window and to word the answer; a breakpoint set while the launch was in flight could stop the program and still be answered with "nothing is armed". The wait no longer depends on what is armed at all (see #823), so there is no window to choose and no snapshot to go stale: the arming is read when the answer is built and only words it (#826)
