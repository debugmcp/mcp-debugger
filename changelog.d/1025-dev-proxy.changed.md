**The dev proxy (`tools/dev-proxy`) speaks both MCP protocol eras and starts its backend on first use.** The client-facing side is served through the SDK's stdio entry, so a probing client — Claude Code's v2 runtime — lands on the current 2026-07-28 revision while an `initialize` client keeps the 2025 era; towards its backend the proxy negotiates the era too, on either transport — over stdio on the backend's own pipe, so the backend still starts once and an older build falls back to the 2025 era — and `dev_server_status` reports `protocolEra`/`protocolVersion`, with a note before the first start that the backend starts on first use. Resource subscriptions are translated across eras (one `subscriptions/listen` to a 2026 backend, one `resources/subscribe` per URI to a 2025 one) and re-expressed after every backend restart, so a `dev_rebuild_and_restart` no longer loses them; a subscription to a resource the restarted backend no longer has is dropped instead of failing the rest. The backend now starts on the first request that needs it rather than at process start: a v2 client's `auto` negotiation over stdio probes `server/discover` on a disposable sibling proxy process, which used to start a backend of its own and race the real proxy for `DEV_PROXY_PORT` (measured: two backends per connect). The proxy exits when the SDK transport closes the wire by itself, not only on stdin EOF. Completes step 2 of #1025 for the development loop.
