**A stop where no frame has source says so, on every answer.** A frame counted as program code whenever the adapter's policy did not know its name as runtime, so a `step_out` of a Rust `main` — which lands in the standard library's start-up shim, ten frames CodeLLDB can only name by symbol — answered with no `note` and no `noProgramFrame`, a symbol label as `location.file`, and a nameless `void` "local". A program frame is now one the policy keeps **and** that names a source, so it can be opened at a line; the same definition already chose which thread a pause is anchored on. The step, pause and wait answers, `get_stack_trace`, `get_local_variables` and `evaluate_expression` carry `noProgramFrame: true` and a sentence that does not call such a frame runtime (`…all 10 frames are internal/runtime or have no source… Code without source is a runtime's or a library's, or your own built without debug information…`); the locals clause reads `…belong to '<frame>', a frame without source`. `location`, `snapshot.frames` and the `frame` of the inspection answers carry `unresolvedSource: true` when their `file` is a label, as `get_stack_trace` already did. Under CodeLLDB a variable with no name (the value a function that returns nothing "returned", shown after a step out) is no longer listed, glibc's `__` aliases of the syscall wrappers (`__nanosleep`) are hidden like the wrappers, and the walk-down note of `get_local_variables` calls a top frame `runtime/stdlib` only when the policy does. What `get_stack_trace` lists is unchanged.
