**A Java stop in a class with no line breakpoint answers the path of its source.** The JVM names a frame's source relative to its source root (`com/acme/App.java`, or a bare `PauseTest.java`), and the JDI bridge only knew a class's path from a line breakpoint set on that class. A pause, a function-breakpoint stop, an exception or a step into another class therefore answered a name that `get_source_context` and `set_breakpoint` could not open, with no `context`. The bridge now looks the relative path up under the source roots the session knows: the root a line breakpoint's path shows (the path ends in the class's package path, so what precedes it is where the tree starts), `sourcePaths`, and for a launch the program's and the working directory, their ancestors (for a class in a package only: a bare file name is looked up where the launch points, not above it) and the classpath's directories. The first root the file exists under wins; the stop answer then carries `context` and the stale-build check. An attach knows no root until a breakpoint shows one or `attach_to_process` passes `sourcePaths`, which the Java adapter now reads. A class with the same simple name as one that has a breakpoint, in another package, reports its own file when that file is under a root, instead of borrowing the breakpoint's. A source under no root is still answered by its relative name.
