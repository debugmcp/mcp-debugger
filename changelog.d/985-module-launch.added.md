**Python launches can run a module** — `start_debugging { scriptPath, dapLaunchArgs: { "module": "pytest", "cwd": "/proj" }, args: [...] }` now reaches debugpy as a `python -m pytest` launch. Every launch used to carry `program`, filled from `scriptPath`, and debugpy refuses the pair (`"program", "module", and "code" are mutually exclusive`), so a module launch could not be expressed at all. The Python policy now declares its launch-target keys (`program`, `module`, `code`), the connection manager fills `program` only when the launch config names no target of its own, and the Python launch transform drops `program` beside a `module` or `code` target and says so in the launch answer (`dapLaunchArgs.module: launched as a module (python -m); program is not sent …`). `scriptPath` still names an existing file — the package's `__main__.py`, or the test file a `pytest` run is about — and `cwd` is what `-m` puts on `sys.path`, so set it to the project root (the default is the script's directory).
