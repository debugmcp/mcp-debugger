**A JavaScript attach by inspector URL goes through the attach flow, and an attach js-debug refuses fails at once in its words** — `attach_to_process { adapterConfig: { websocketAddress } }` reached js-debug as a `launch` whose body said `request: 'attach'` (the policy took its attach branch only on a numeric port): launch-branch keys on an attach, and a launch parent recorded for child adoption. The attach branch is now keyed on the request alone, honours `websocketAddress` without a port (`continueOnAttach` applies, so an `--inspect-brk` target runs briefly before the post-attach pause), accepts a numeric-string port, and refuses a port-less attach without a URL instead of launching. The handshake no longer swallows a rejected `attach` or `launch` request — it runs in the server process, where console output is silenced, so the rejection was invisible — and when js-debug answers the attach with its own error response the attach fails immediately: `Failed to attach: The javascript debug adapter rejected the attach request: …`. A stale proxy error from an earlier run is cleared before each attach attempt (#896)
