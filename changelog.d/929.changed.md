**`IDebugAdapter.getDefaultLaunchConfig` is removed from `@debugmcp/shared`** (a required member, as `AdapterPolicy.isSessionReady` was in #823). Nothing called it: the only launch defaults ever applied are the session core's `{ stopOnEntry: false, justMyCode: true }`, merged before the adapter's `transformLaunchConfig`, and the values the adapters declared contradicted that — .NET and Java said `stopOnEntry: true`, most said `cwd: process.cwd()` (the server's directory; the launcher defaults `cwd` to the program's). Adapters that still define the method keep compiling; a caller would not, and none is known. Launch behaviour is unchanged (#929)
