**Step answers join the stop snapshot, and repeated stops report only what changed** — `step_over`/`step_into`/`step_out` now carry the same `snapshot` as the arrival answers (#982), composed once per answer even on adapters that step once per token position (Dart's same-line repeats). A later stop in the same frame — the next step, or a `continue_execution` → `wait_for_stop` loop over one breakpoint — replaces `locals` with `changedVariables: { name: { before, after } }` (new variables appear with `before: "<undefined>"`; an empty `{}` means the executed line changed nothing visible), so stepping through a loop costs a diff per answer instead of the full scope every time. Frame identity is the locals anchor's name + file + visible depth: any mismatch re-emits full `locals` and rebases, never a wrong diff; the same stop answered twice never diffs against itself; the cache resets on relaunch/re-attach (#983)
