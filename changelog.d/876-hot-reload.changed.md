- **`hot_reload` replaces `redefine_classes` and adds Flutter hot reload** — one tool applies changed code to the running program and keeps its state: on a Flutter session it is the SDK adapter's hot reload (the app must have started; the reassemble runs `build()`, so a breakpoint there is reported by the call as the stop with its location and snapshot — measured ~150 ms after the request; widget state, counters and timers survive; a reload sent to a paused program lands when it resumes), on Java it is the class redefinition the tool always did (the answer is unchanged). The behaviour is one `AdapterPolicy.liveUpdate` member — the events the worker forwards for it (`flutter.appStart`/`flutter.appStarted`), the request or the refusal, whether code changed, whether the update may stop the program — so a third adapter with a live update implements one object. **`redefine_classes` is a deprecated alias**: still accepted with the same arguments, answered with a `warning`, no longer advertised by `tools/list`, removed at 1.0; the tool count stays at 29.
