**`attach_to_process` answers by its `verifyTimeout`, and a timed-out request on an attach session no longer recommends `restart_debugging`.** When nothing answered the verification's `threads` request at all, the call waited for the parent's backstop, five seconds past the window, and reported "no threads reported within 20000ms (last failure: … within 25s …)". The wait now ends with the window. And the timeout message told every session to "Try restart_debugging to relaunch the session", which an attach session cannot do: for a session that attached, it now says to attach again with `attach_to_process` (#1213).
