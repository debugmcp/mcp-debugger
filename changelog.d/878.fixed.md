**The .NET bridge no longer drops netcoredbg's last DAP frames** — the TCP-to-stdio bridge ended the proxy's socket on the child's `exit` event, but Node fires `exit` when the process ends and `close` only once its stdio has drained, so an `output`/`exited`/`terminated` frame netcoredbg wrote just before exiting could still be in the pipe when the socket was closed (the same class as #860). The bridge now ends the socket on `close`, stops forwarding proxy bytes to a stdin that has no process behind it, logs an in-flight stdin error instead of dying on it, and says in its stderr when netcoredbg closed and when the proxy's socket errored, so the proxy log explains the next report of this class (#878)
