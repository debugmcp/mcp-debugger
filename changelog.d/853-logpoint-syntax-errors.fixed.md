**A JavaScript logpoint or condition that does not parse says so, where the breakpoint is** — js-debug accepted a `logMessage` whose `{expression}` had a syntax error (or a malformed `condition`), never fired it, and reported it as a plain `Unbound breakpoint`; its only word on the cause was a `Syntax error setting breakpoint with condition …` line in the debuggee's stderr stream. Now `set_breakpoint` on a JavaScript session refuses a `logMessage` whose interpolations do not compile, with V8's own message (`Invalid logpoint: logMessage expression {n +}: Unexpected token ')'`), the way an `expectedContent` mismatch is refused; and for a plain `condition` js-debug rejects, the proxy correlates js-debug's stderr line with the request in flight — the `setBreakpoints` it sent, or the `attach` during which js-debug compiles the breakpoints it buffered — and stamps it onto the breakpoint record, so `list_breakpoints` and the launch's unbound-breakpoint warning carry the reason. The stderr line is still delivered as output (#853)
