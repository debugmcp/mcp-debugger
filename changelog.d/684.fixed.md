**JavaScript launch reports stops in the source view its breakpoints were set in** — the adapter sent js-debug `sourceMaps: false` for every `.js` program (js-debug's own default is `true`), so a compiled TypeScript app launched from `dist/index.js` bound its `src/*.ts` breakpoints and then reported every stop, frame, local and step location in `dist/*.js`, with nothing in the responses saying the two were the same code. Source maps are now on for `.js` programs too, with the same default `outFiles` (`**/*.js`, excluding `node_modules`) and `resolveSourceMapLocations` the `.ts` path always had, so `get_stack_trace`, `get_local_variables`, `evaluate_expression` and the step locations all report `src/*.ts`, and `list_breakpoints` verifies a `.ts` breakpoint under its own path. A program without maps is unaffected; pass `adapterLaunchConfig: { sourceMaps: false }` to see generated locations instead — honoured for `.ts` programs too now, where it used to be forced on (#684)
