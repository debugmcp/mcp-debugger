**`pi install npm:@debugmcp/mcp-debugger` registers the server with pi's built-in MCP support (pi 0.99+)** — the package ships a pi extension that calls `pi.registerMcpServer()`, which is how pi lets a package add a server, so the debugger's tools reach pi without the community `pi-mcp-adapter`. Before this, on pi 0.99+ the install added the skill but not the server: the package declared it only through the adapter's `pi.mcp` manifest entry, which pi itself ignores. The extension runs the CLI installed next to it (no `npx` download at startup), with `deferred` exposure, so pi lists the debugger in its system prompt and the model loads the 28 tools with `tool_search`, and a 180 s request timeout for slow launches. The adapter-only `pi.mcp` entry and `pi.mcp.json` are removed; an install alongside pi-mcp-adapter 4.x still works through pi's built-in MCP, and pi older than 0.99 ignores the extension (#841)
