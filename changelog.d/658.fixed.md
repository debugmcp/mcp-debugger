**A crashed HTTP client's debug sessions — and any paused attach target they hold — are released within minutes, not 30** — an MCP SDK client keeps a GET stream open, so the server sees the socket close the moment the client exits without `DELETE /mcp`, but the reaper treated that session like any streamless one and waited out `MCP_HTTP_STALE_SESSION_MS` while the orphaned proxy held the attach target frozen, invisible to every other client. A session that once held a stream and has been streamless and silent longer than `MCP_HTTP_STREAM_LOST_SESSION_MS` (default 2 min; `0` falls back to the stale window) is now reaped; a reconnecting stream or any request resets the window, and pure-POST clients, whose liveness is unobservable, keep the 30-minute window. Reap log lines name the debug sessions released, and `GET /health` gains per-session `details` (open streams, `streamLost`, idle time, held debug sessions with state) so an operator can see what an orphan holds without `ps` (#658)
