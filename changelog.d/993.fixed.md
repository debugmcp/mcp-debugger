**Python debuggees on Windows no longer run under `pythonw.exe`, so the children they spawn keep working** — the adapter had been swapped for a sibling `pythonw.exe` to keep console windows off the screen (#215), and debugpy's launch `python` defaults to the adapter's own interpreter, so the launcher and the debuggee ran windowless too; a debuggee child that inherited a standard handle (pytest-xdist's execnet workers under a venv) then died inside `subprocess` with `OSError: [WinError 6] The handle is invalid` before it existed. The adapter now runs under the session's interpreter on the hidden console the proxy's `windowsHide` spawn already gives it, which the launcher and the debuggee inherit: measured at zero new visible console windows over a full breakpoint session, `pytest -n 2` spawns its workers, and `sys.executable` in the debuggee is `python.exe` (#993)
