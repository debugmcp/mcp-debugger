**PyPI launcher re-aligned with the server it launches** — `debug-mcp-server-launcher` had drifted: `--version` printed a hardcoded 0.11.1 (six minors stale; it now reads the installed package metadata, so the release-stamped `pyproject.toml` is the single source of truth), the recommended `http` (Streamable HTTP) transport was missing (added; `sse` still works but prints a deprecation warning), and Docker mode ran `docker run -it` against piped stdio — a known "the input device is not a TTY" failure — with no workspace mount, so the container could not see the caller's files (now `-i --rm -v <cwd>:/workspace`). The launcher's unit tests now run in CI, which previously executed them nowhere. (#641)
