**`set_breakpoint` warns when the TypeScript source is newer than the compiled file js-debug binds it through** — the answer echoes the line from the `.ts` you named while js-debug binds through the generated `.js`'s source map, so a `dist/` older than `src/` used to put the breakpoint on a different statement than the one shown, with no signal. The server now locates the compiled file (the nearest `tsconfig.json` that names an `outDir`, or `dist|build|out|lib` under the nearest `package.json` when none does, then a sibling `.js`; only a candidate whose `.js.map` names the source counts) and, when it is older than the source, adds a hedged `warning` naming both files and their mtimes; `step_*`, `wait_for_stop` and `pause_execution` carry the same sentence as a `note` at such a location. Per-language knowledge lives on a new optional policy hook, `AdapterPolicy.generatedFileCandidates` (#938)
