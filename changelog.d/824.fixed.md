**C/C++, Rust and COBOL stacks on Windows hide the CRT and NT runtime frames** — the LLDB display filter knew glibc's start-up names and POSIX syscall wrappers but none of their Windows equivalents, and the source rule did not recognise CodeLLDB's path-less `@symbol` label (`source: {name: '@NtWaitForSingleObject'}`, which the anchor resolver carries into `file`), so a paused Windows program showed `NtWaitForSingleObject`, `WaitForSingleObjectEx`, three winpthreads frames, `__tmainCRTStartup`, `mainCRTStartup`, `BaseThreadInitThunk` and `RtlUserThreadStart` around its one line of `main`, with no `hiddenFrames`. The filter now treats an `@symbol` file as "no source", knows the Windows CRT start-up, the kernel32/ntdll thread and wait plumbing and `pthread_*`, and recognises MSYS2's `mingw64/include` and the MSVC `vctools` tree as system paths — under the same name + no-user-source rule, so a user function named `Sleep` with a workspace path is kept; the system-path roots are anchored, so a project's own `lib/` folder no longer counts as one. Inspection anchors on the first visible frame (for a program asleep in `std::this_thread::sleep_for`, that header frame rather than `main`), and a stop that sits in a hidden frame of the anchored thread is disclosed as `pausedFrame` (the #672 rule). On Linux the `pthread_*` rule also hides glibc's nptl frames — `pthread_*`, `__pthread_*` and `___pthread_*` — whose `./nptl/` source the filter already classified as a system path (#824)
