**The server runs on the v2 MCP TypeScript SDK** (`@modelcontextprotocol/server` 2.4 with `node`, `client` and `core`) in place of `@modelcontextprotocol/sdk` 1.x. The wire protocol now supports 2026-07-28 alongside 2025-11-25 and the ones before it on both transports; every tool, resource and prompt answer and the legacy HTTP session contract (`Mcp-Session-Id`, the 400/404 bodies, the Host/Origin allowlist) are unchanged, but the stale-session sweep no longer closes debug sessions. What moves: a client that still sees `MCP error <code>: ` in front of a tool error's message is seeing its own SDK's prefix, which the v2 client no longer adds (the server's JSON-RPC bodies carried the bare reason already); the server log records the protocol version each client negotiates (`[MCP Server] Client initialized`); the bundles target Node 22, the floor the package already declared.
