**Python logpoints with f-string conversions or format specs are refused at `set_breakpoint` time with the expression form that works** — debugpy evaluates the text inside each `{...}` group of a `logMessage` as a Python expression at hit time rather than parsing an f-string field, so `{entry!r}`, `{x!s}`, `{x!a}` and `{total:.2f}` succeeded when set and logged `invalid syntax (<string>, line 1)` (or `invalid decimal literal (<string>, line 1)`) when hit; `PythonAdapterPolicy.validateLogMessage` now refuses top-level conversions and format specs up front and names the working replacement (`{repr(entry)}`, `{str(x)}`, `{ascii(x)}`, `{format(total, '.2f')}`) (#1334)
