**A breakpoint id that two breakpoints share no longer moves or credits the wrong one.** js-debug numbers a child process's breakpoints from one counter before the child is attached and from another after, so a breakpoint added to a paused child can come back with the id an earlier one still holds; its bind event and its stop then name both. The id lookups took the first record that held the id. An adapter id now names a record only while exactly one record holds it: an event under a shared id goes by its location, and no hit is credited by it. Each record still gets its own state from the `setBreakpoints` answer, which is positional (#1220).
