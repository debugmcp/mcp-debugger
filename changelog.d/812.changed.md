`start_debugging { dryRunSpawn: true }` is now a query that leaves the session exactly as it was (#812). It runs the launch preparation in the server — toolchain gate, adapter and environment checks, the launch transform (compiling a source-file program where the language does), executable resolution, the adapter command — and answers with the command the launch would run plus the configuration warnings. Nothing else changes: the answer's `state` is the session's current state, a running or paused program keeps running, and the previous run's output, exit code and last stop stay readable. Previously a dry run was a launch attempt that rode the proxy worker: it tore down a live program, reset every per-launch record and ended the session `stopped`. Attach-shaped configurations are refused, since preparing an attach acts on the target process.
