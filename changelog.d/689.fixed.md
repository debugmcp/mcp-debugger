**`http`/`sse` validate `--port` and announce the port the socket actually bound** — the option had no parser, so `-p abc` failed with Node's own `options.port should be >= 0 and < 65536. Received type number (NaN)` (naming an internal, not the flag, not the value typed), `-p 3001x` silently bound 3001 because `parseInt` stops at the first non-digit, and `-p 0` logged `listening on 127.0.0.1:0` while the OS-assigned port was visible only in `/health`. The value is now resolved the way `--bind` is: only an unsigned integer in 0-65535 is accepted, and anything else is refused by name before anything is announced or built — `--port value 'abc' is not a port number; give an integer 0-65535 (0 lets the OS choose). The server was not started.` (an in-range-looking `70000` is told it is above 65535 instead). The `listening on` / `endpoint available at` startup lines are emitted from the socket's `listening` event, carry the bound port with IPv6 hosts bracketed, and the endpoint is mirrored to stderr — both transports silence the console, so the logger alone left a plain `-p 0` with nowhere visible to read the port. The dev-proxy applies the same rule to `DEV_PROXY_PORT` instead of dialing `127.0.0.1:NaN` for 30 s (#689)
