**`get_stack_trace` no longer sends a caller round in a circle, and an ended session is explained by every inspection tool.** Two guidance gaps. On a stop where no frame is program code, `get_stack_trace` ended its note with "get_stack_trace with includeInternals: true lists the frames" — including for a caller who had just passed `includeInternals: true` and was looking at every frame. That clause is now added only by an answer that has not shown the thread's whole stack (a pause or step answer on a thread with more than one frame), and never by `get_stack_trace` itself. And after a program ran to completion, `get_stack_trace`, `get_scopes`, `get_variables` and `evaluate_expression` answered a bare `Session is terminated: <id>` where `get_local_variables` explained the state. All five now carry the same `message`, worded for what the session is: a launched program is run again with `restart_debugging`; an attach session, which `restart_debugging` refuses, is attached again with `attach_to_process` (it used to be told "Use restart_debugging" as well); a child session names its parent. The `error` text is unchanged. (#1141)
