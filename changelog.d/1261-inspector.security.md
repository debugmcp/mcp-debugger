**An attach by processId no longer leaves an unauthenticated Node.js inspector it opened listening in the target** — the inspector `attach_to_process { processId }` opened stayed open on `127.0.0.1:9229` after the session ended, and any local process could connect to it and run code in the target for as long as the target ran. The server now closes an inspector it opened and identified at the endpoint it attached to (the `port` passed, else `127.0.0.1:9229`) when the last session of this server using it ends (the one that opened it, or another that shares it), and the answers say so; like any inspector it is open while the session lasts. It stays open, and the answers say so, where the server could not identify it — a target started with `--inspect-port=<n>` and attached by processId without that port, whose inspector the signal opens on `<n>`, where the attach did not look (#1310) — or could not confirm the close (`not confirmed closed: …` with the reason). A server killed before its sessions end closes nothing (#1261)
