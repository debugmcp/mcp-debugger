**A js-debug child target is configured with the caller's intent whichever connection its `startDebugging` arrived on** — the caller's `request`/`stopOnEntry` and an attach parent's forwardable extras (`localRoot`/`remoteRoot`, `sourceMaps`, `skipFiles`, …) were threaded into a child config only on the parent connection, by `MinimalDapClient` before it called `createChildSession`. A `startDebugging` that js-debug delivers on a child or release connection — a fork's request lands on its parent target's socket — reached the child session manager with js-debug's bare `{type, name, __pendingTargetId}`, so those extras never reached the forked target; and a bare config that goes on to be adopted reads the absent `stopOnEntry` as "wait for an entry stop, then force one" — the 15 s wait and forced pause of #704, and a readiness signal that late. The enricher is now a `ChildSessionManager` option applied at the top of `createChildSession`, the one place both entry points meet, so every adoption and every release is configured the same way (#712)
