- **`restart_debugging` uses the adapter's own restart when it offers one — a Flutter hot restart** — when the adapter advertises `supportsRestartRequest` (the Flutter adapter does, in a DAP `capabilities` event once the app has started; no other adapter does today), the DAP `restart` request is sent instead of terminate + relaunch: `main()` re-runs in the same process and the first breakpoint is reached again about half a second later (measured on Windows desktop and Chrome), the answer carries `data.hotRestart: true`, the output buffer is kept (no `outputReset`), breakpoints stay armed in the adapter, a `stopOnEntry: true` launch stops at entry again, and a Flutter attach session can be restarted this way too. The proxy worker now forwards the adapter's `capabilities` events merged into the session's capabilities, treats `restart` as a resume, and re-arms the hidden entry breakpoint's relabel for the re-run. Every other language keeps the relaunch, now described by the answer as before (`outputReset: true`) (#876)
