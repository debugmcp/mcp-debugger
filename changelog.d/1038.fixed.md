**Two agent-facing papercuts on the LLDB-based adapters and on `expectedContent`** — CodeLLDB's own console housekeeping (the "Console is in 'commands' mode" banner, its `Executing script:` markers, the `Launching:` and `Launched process` lines, and `Attached to process` on an attach) landed in `get_output` ahead of any program output on C/C++, Rust and COBOL launches, consuming the cursor and reading as the program's own; the shared LLDB policy now drops those lines on the `console` category only (the engine's "Process exited with code N." stays, as does the same text on stdout or stderr). And `set_breakpoint` with an `expectedContent` that was the whole statement minus the line's trailing `;` or `.` — the one character an agent quoting a statement drops — got the "matched as a substring, confirm this is the intended line" warning; that match is now exact-equivalent (`matchQuality: "terminator-stripped-exact"`), and a partial statement still warns (#1038)
