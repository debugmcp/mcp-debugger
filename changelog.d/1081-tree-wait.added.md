**`wait_for_stop` is tree-aware — set a breakpoint in the child's code, start the parent, wait** — a wait on a session now observes it and every child session its program spawned (Python, on by default) and answers for the session a fixed priority names: the session itself when it is paused, else the first paused descendant, else the session itself when it has ended; `sessionId` names the session the answer is about (inspect, step and continue with it), `children` lists every descendant with its state, and an ended child alone never completes the parent's wait. The `start_debugging` and `restart_debugging` answers carry the same `children`, plus `childrenReleased` (children run undebugged beyond `DEBUG_MCP_MAX_CHILD_SESSIONS`) and `childrenClosed` (a relaunch closes the previous run's children; a Flutter hot restart keeps them); `detach_from_process` on an attach root detaches the children first and leaves them running (`childrenReleased`, or `childrenClosed` with `terminateProcess: true`); `close_debug_session` says `childrenClosed` when it took descendants with it, `processEnded: true` for a debugpy child it ended, or `released: true` for an attach root whose targets run on (#1005, #1081).
