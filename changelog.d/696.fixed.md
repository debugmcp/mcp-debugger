**Package tests run from the package directory** — `pnpm --filter @debugmcp/adapter-ruby test` (likewise go, cpp, dotnet and codelldb-common) failed at setup before a single test ran: with no package-local config, vitest walks up to the root `vitest.config.ts`, whose `setupFiles` entry was cwd-relative and so pointed at a `tests/vitest.setup.ts` inside the package that does not exist. The root entry is now absolute, like every alias beside it, so a package run uses the same setup file as the root run — the leak guard and the per-test mock and env reset included. The three package-local configs that only duplicated the root (rust, mock, python) are removed: they skipped that setup, which let a mock leak between two python tests standalone while the root run passed, and rust's could not resolve `@debugmcp/codelldb-common` from source on a checkout with no `dist/`. `shared` and `javascript` keep theirs (each carries a package-specific coverage block). Two remaining standalone failures are not this class: adapter-dotnet's two bridge-path tests need a built bridge and a repo-root cwd (#743), and adapter-java has no package-local tests to run (#696)
