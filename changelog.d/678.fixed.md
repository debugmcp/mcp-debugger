**`justMyCode: false` lets a JavaScript launch step and pause inside dependencies, and a lost step or pause says why** — the launch transform always blackboxed `**/node_modules/**` through js-debug's `skipFiles`, so `dapLaunchArgs.justMyCode: false` (the documented way to debug dependency code) changed nothing: a `step_over` issued at a breakpoint inside a dependency returned `pending: true` and never landed, and `pause_execution` on a launched HTTP server never stopped (js-debug's smart-stepper keeps stepping while the program is in a skipped frame, and on a server that is where every pause lands). `justMyCode: false` now drops `node_modules` from the skip list and turns js-debug's smart-stepper off — the same pair attach got in #513 — so the step lands on the next line of the dependency and a pause on an idle server lands as soon as any JavaScript runs, in an internal frame if that is where the program is (with the stepper off, steps also stop in unmapped generated helpers it used to skip). On the default launch the two `pending: true` responses now explain themselves: a step issued from a skipped frame names the frame, the smart-stepper and the `justMyCode: false` remedy, and a pending pause names the stepper and the remedy; both stay silent once the stepper is off. Separately, a step whose stop was a breakpoint or exception rather than the step — observed when js-debug resumed a lost step and the next request re-hit the same breakpoint — is reported as `Stepped over; stopped on 'breakpoint' rather than on the step itself` with `stopReason`, and says when the program is back at the line the step was issued from, instead of a bare "Stepped over" at a line the step never reached (#678)
