**JavaScript: a function breakpoint no longer hangs a program that forks.** With any function breakpoint set, a forked Node child was never adopted as a child session: its row said `running` for 30 s and then disappeared, the answers said "1 child process was released to run undebugged (adoption failed…)", and the program never ended, because the fork was in fact stopped on the line breakpoint it had inherited, with no session to resume it. js-debug has no `setFunctionBreakpoints` and sends nothing back for a request it does not know, and the fork's connection was sent that request raw, during the adoption and for a `set_breakpoint {function}` on a child's id. Function breakpoints are armed in the session's own program (the CDP bridge), so a child's are now answered at once as what they are, unverified with "Function breakpoints are not armed in a child session…", and nothing is sent. Python children keep their function breakpoints: debugpy has the request.
An adoption that fails for any other reason is also cleaned up where the child is. An attach that has already failed ends the handshake before `configurationDone` goes out, so the target is still pending and the throwaway attach releases it; a failure after `configurationDone` lets the child go with a `disconnect` on its own connection, which is the connection the adapter has bound it to by then (a second attach to it is never answered) (#1219).
