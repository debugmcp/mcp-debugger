**Launch failures are torn down the way attach failures are, and a dry-run timeout carries the proxy-log pointer** — when `start_debugging` fails after the proxy exists, the proxy's listeners are now removed before it is stopped, the session's mirror record is cleared with the worker that hosted it, and a `stop()` that fails is logged instead of turning the reported failure into a rejection (attach already did all of this). A dry run that never reports back now returns the same `data.proxyLogPath` a thrown launch failure returns and writes the same full failure record to the server log; its `Dry run timed out after Nms` message is unchanged (#582)
