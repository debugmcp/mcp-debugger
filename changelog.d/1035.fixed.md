**C/C++: a binary compiled on the host is no longer reused by the Docker server over the same bind mount** — the adapter's `.debug-mcp/` cache decided reuse by file times alone, so a `hello.cpp` built on a Linux/macOS host was launched as-is inside the container (same path, same name), where its DWARF named the host's paths and every line breakpoint stayed unbound. Each compile now writes a build record beside the output (`<binary>.build.json`: compiler and version, flags, platform, architecture, whether it was built in the container, the source path as compiled), and a cached binary is reused only when the record matches the current environment and the source is not newer; a binary built before records existed is rebuilt once. The COBOL half of #1035 (one shared `latest.json` and prune pool per program across host and container, root-owned leftovers) is deferred with its reason on the issue; `docs/docker-support.md` now recommends `--user $(id -u):$(id -g)` for a bind mount (#1035)
