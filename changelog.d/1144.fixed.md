**A breakpoint that binds no longer repeats its description in `warning`.** Every successful COBOL function or paragraph breakpoint carried its bind description (`2000-COMPUTE (paragraph of HELLO) -> hello.cob:42`) in `warning` as well as `message`, and a C/C++ or Rust line breakpoint did the same with CodeLLDB's `Resolved locations: 1`, so an agent that treats a `warning` as a problem saw one on every clean bind. `warning` now carries the adapter's message only when the breakpoint is unverified; `message` carries it either way.
