**A breakpoint set while a launch is still starting reaches the debugger at once** — `set_breakpoint`, `remove_breakpoint` and `clear_breakpoints` on a session whose `start_debugging` had not finished its handshake only updated the stored set: the adapter cannot take a breakpoint that early, and the proxy had already taken its own snapshot. Nothing sent the change until the launch's wait was over — up to 30 s, with the program running past the breakpoint all the while (measured: a breakpoint whose condition became true 11 s into the run stopped the program at 33 s) — and a removal was never sent at all, leaving a breakpoint the session no longer listed. The launcher now compares the stored set with what the proxy started with as soon as the program is launched, and sends the difference before it starts waiting for a stop, clearing what was removed (#851)
