**`outputTail` on a non-zero exit drops adapter housekeeping and preserves leading crash causes** — Both `outputTail` and a failed launch's output quote now join consecutive chunks of the same category before splitting on newlines and end the line after an 8,192-character `truncated` chunk. On a non-zero exit, `outputTail` quotes the last 8 lines of the program's own output in arrival order across streams (excluding adapter `console` lines plus Node inspector, js-debug breakpoint syntax-error, JVM JDWP, and CodeLLDB `Stop reason:` lines, while reclaiming Dart/Flutter's explicit-category `console` output such as `dart:developer` `log()` records, test-result lines, and Flutter tool launch/reload lines without taking category-less logpoints). When a recognised runtime fatal-error header (`libcob: … error: …`, `libstdc++` `terminate called …`, or in Rust the main thread's panic line `thread 'main' … panicked at …` / `has overflowed its stack`; a C program ending by `assert` or `abort` has none) sits above the last 8 lines — including on Linux where CodeLLDB merges pty streams into `stdout` — or when all 8 fall inside one `stderr` block longer than 8 lines, `outputTail` quotes that head line and the 3 after it, `"... (N lines omitted)"`, and the last 3 lines; Python keeps its plain last 8 lines so both the user's frames and the trailing exception stay visible (#1277)
