**Concurrent launch-shaped calls on one session are refused instead of tearing each other down** — `start_debugging`, `restart_debugging` and `attach_to_process` had no in-flight guard beyond the session state, and the state cannot tell "a launch is being awaited" from "the program is running": a JavaScript launch projects `running` the moment its child session is adopted while `start_debugging` is still parked on the launch barrier. A second call in that window passed the guard, disposed the barrier the first call was awaiting, and both returned `success: true` for a proxy that was being torn down. One in-flight claim per session, shared by launch and attach and taken before the first await, now answers the second call with *"A launch is already in progress for this session … wait for it to complete before calling restart_debugging"*; a sequential second `start_debugging` still supersedes the first launch as before, and a session left `initializing` by a readiness wait that hit its ceiling can be restarted again — the state-based check had refused it forever (#711)
