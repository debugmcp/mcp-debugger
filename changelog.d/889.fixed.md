**Windows: debug adapters are no longer spawned detached, which made every Delve launch 8–13 s slow.** Node's `detached` is `DETACHED_PROCESS` on win32 — the adapter gets no console — and Delve pays for that at every process it creates: measured on Windows 11, `dlv version` takes 0.1 s with an inherited or hidden console and 2–3 s detached, and a debug-mode `launch` of a trivial Go program spent 6 s in `go build` plus 4 s starting the debuggee instead of ~1 s in all — enough, under load, to hit the proxy's 30 s launch limit (issue #889's pre-push flake). The adapter keeps `windowsHide` (a hidden console) on Windows and stays detached on POSIX, where its own process group is what the shutdown signals; the Windows tree-kill is `taskkill /T` and never needed the group. The Go integration suite went from 48 s to 15 s on the same machine; Python, JavaScript, CodeLLDB, Java and Ruby adapter binaries start in the same time either way (#889)
