**A Python program that starts another Python process no longer hangs under the debugger** — debugpy's sub-process debugging was on because the launch never named `subProcess`, so pydevd hooked every Python child the program started (`subprocess`, `multiprocessing`, pytest-xdist workers) and held it until a debug client attached to it; this server never did, so the child never ran, the parent waited on it, and the session reported `running` with no stop and no exit. The Python launch and attach transforms now default `subProcess` to `false`: children run undebugged, and an explicit `subProcess: true` is forwarded with a warning that names the hang. Debugging the children themselves is the feature half of #1005 (#1005)
