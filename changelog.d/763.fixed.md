**Detaching from a C/C++, Rust or COBOL target on Windows no longer kills it after a step** — CodeLLDB's Windows detach resumes every thread with the resume state its last stop left behind, and after a `step_over`/`step_into` that state is still "stepping", so the thread single-stepped with no debugger attached and the process died with `STATUS_SINGLE_STEP` (`0x80000004`) — measured every time on Windows 11 with CodeLLDB 1.11.8 (LLDB's `ProcessWindows::DoDetach` since LLVM PR 115712). `detach_from_process` now sends a DAP `continue` ahead of the `disconnect` when such a target is paused (`data.resumedBeforeDetach: true`); if the debugger refuses the continue the detach still proceeds and `data.warning` says why the target may not survive. The session's own `disconnect` is also no longer followed by a second one from the worker's shutdown (#763)
