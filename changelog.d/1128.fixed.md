**A parent's end summary no longer says the run hit no breakpoint after a child session stopped on one.** With child sessions (Python and JavaScript), the documented flow — a breakpoint in the child's code, start the parent, wait — ended with the parent answering "The program ran to completion (exit code 0) without hitting any breakpoint. Verified but never hit: child.py:12", although a child session had stopped on that line (JavaScript reported the breakpoint as never bound as well). The summary was read off the launched process alone. A stop on any descendant is now counted for its ancestors, and a session whose tree stopped answers "Its child sessions stopped 2 times during this run." with no breakpoint listed as unhit — also when the child was closed before the parent ended.
