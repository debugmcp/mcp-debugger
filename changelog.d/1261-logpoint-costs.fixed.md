**The docs state everything a logpoint costs** — the README still called logpoints "prod-safe value watching on hot paths". It now names three costs, and the tool reference explains each. The process keeps a debug endpoint open for as long as you watch, and an attach to a Node.js process by PID leaves its inspector listening on `127.0.0.1:9229`, unauthenticated, after detach and close (#1261); the JavaScript guide and the debugging skill no longer present that only as a convenience. Each hit costs time. And in Python, JavaScript and Dart a function that holds any breakpoint runs slower as a whole: V8 and the Dart VM stop optimizing it, and debugpy traces its every line. Newly measured: the function gets its speed back when the logpoint is removed or the debugger detaches, and attach mode costs no more than launch mode. The roadmap is refreshed for v0.27.0, which changed documented behavior and so does not start the 1.0 soak clock (#1218, #1261)
