**The docs state the three known costs of a logpoint** — the README still called logpoints "prod-safe value watching on hot paths". It now names three costs, and the tool reference explains each. A debugger stays attached for as long as you watch, which for a running Python, JavaScript or Dart process means an open debug port, and an attach to a Node.js process by PID leaves the inspector it opened (`127.0.0.1:9229` by default) listening, unauthenticated, after detach and close (#1261); the JavaScript guide, the debugging skill and the server's workflow prompt no longer present that only as a convenience. Each hit costs time. And in Python, JavaScript and Dart a function that holds a line breakpoint of any kind runs slower as a whole while it holds it: V8 and the Dart VM stop optimizing it, and debugpy traces its every line. Newly measured for JavaScript and Python, attached by port: the function is back at its time without the logpoint by the second recorded call after the logpoint is removed or the debugger detaches, and a hit cost about the same (JavaScript) or less (Python) than in launch mode (#1218, #1261)
