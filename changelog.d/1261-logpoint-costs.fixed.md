**The docs state the three known costs of a logpoint** — the README still called logpoints "prod-safe value watching on hot paths". It now names three costs, and the tool reference explains each. The first is an attached debugger and, for a running Python, JavaScript or Dart process, an open debug port, for as long as you watch. An inspector mcp-debugger opened for an attach to a Node.js process by PID is closed again when the session that opened it ends (#1261). Each hit costs time. And in Python, JavaScript and Dart a function that holds a line breakpoint of any kind runs slower as a whole while it holds it: V8 and the Dart VM stop optimizing it, and debugpy traces its every line. Newly measured for JavaScript and Python, attached by port: the function is back at its time without the logpoint by the second recorded call after the logpoint is removed or the debugger detaches, and a hit cost about the same (JavaScript) or less (Python) than in launch mode (#1218, #1261)
