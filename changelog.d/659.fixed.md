**Protocol errors reach SDK clients with a single `MCP error <code>:` prefix** — every `McpError` thrown from a request handler (argument validation, an unknown tool/prompt/resource, `expectedContent` on an attach session, …) arrived at `@modelcontextprotocol/sdk` clients as `MCP error -32602: MCP error -32602: …`: the SDK copies the thrown error's `.message` — which its own constructor has already prefixed — verbatim onto the wire, and the client-side constructor prefixes it again (the dev proxy had been hiding it with a dedupe). The tools/call, prompt and resource handlers now convert at the JSON-RPC boundary (`WireMcpError`: same class, code and data, bare `.message`), so the wire carries the reason once; in-process throw sites and logs are unchanged (#659)
