**`snapshot.changedVariables` says when a variable is new or gone, instead of inventing a value for it.** A variable that came into scope between two stops was listed as a change from the string `"<undefined>"` — JavaScript's vocabulary for a Java, Rust, Dart or Python local that simply did not exist yet, indistinguishable from a real value, and for js-debug's `Return value` a "change" from `<undefined>` to `undefined`. A variable that left scope silently dropped out, so "unchanged" and "gone" looked the same. Each entry now states which of three things happened, and the side that does not exist is left out: `{ "before": "1", "after": "2" }` for a changed value, `{ "after": "30", "new": true }` for a variable that appeared, `{ "before": "3", "gone": true }` for one that left scope. An empty `{}` still means nothing visible changed. The flags are only set when they are known: the locals a snapshot shows are capped at 20, so a name missing from a list that was cut may only not have fitted — a variable absent from a cut previous list is `{ "after": … }` with no `new`, and one absent from a cut current list is not listed. **Changed shape:** an entry for a new variable no longer has `before`; a client that read `before: "<undefined>"` should read `new: true`.
