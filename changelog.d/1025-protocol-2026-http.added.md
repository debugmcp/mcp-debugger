**`http` speaks the current MCP protocol revision, 2026-07-28, beside 2025-11-25 and earlier — on the same `/mcp` endpoint.** A request carrying the 2026 per-request envelope (`_meta` with `io.modelcontextprotocol/protocolVersion`) is served by the SDK's sessionless handler: `server/discover` answers the supported versions and capabilities, every request stands alone with no `Mcp-Session-Id`, results carry `resultType` and the cache fields, resource notifications flow over `subscriptions/listen` streams, and the 2026 header rules apply (`MCP-Protocol-Version` and `Mcp-Method` on every POST, `Mcp-Name` on the methods that name a tool, prompt or resource; a missing or mismatched one is refused with `-32020`, an unsupported claimed revision with `-32022` naming the supported ones). A 2025-shaped request — `initialize`, a request carrying `Mcp-Session-Id` and no envelope, a GET or DELETE, a claim-less POST — lands on the sessionful app exactly as before, status codes included, so every 2025 client keeps working. An open `subscriptions/listen` stream counts the process as attended for the idle policy, like a 2025 session's SSE stream; a 2026 client that only calls tools is not attending, so with the idle policy turned on its sessions live by tool activity alone. A probing client such as Claude Code's v2 runtime therefore lands on 2026-07-28 against `http` too. `GET /health` reports `listenStreams` and the requests classified per era (`requests.legacy` / `requests.modern`). Browser clients: CORS now allows `Mcp-Method`, `Mcp-Name` and echoes a preflight's requested headers. Step 2 of #1025 completes the protocol move on both transports.
