**`start_debugging` answers a stop with where it is, and `get_stack_trace` carries the stale-build note** — a launch (or `restart_debugging`) that is paused when it answers now carries `location`, the source `context`, and `threadId`/`note` when there is something to say, the way `wait_for_stop` does, read through the same landing read the step and pause answers use. The stale-build sentence (#938, #950) therefore reaches a fast program's first answer instead of waiting for a `wait_for_stop`, and `get_stack_trace` appends it when the file of its top frame is newer than the compiled file the debugger binds it through.
