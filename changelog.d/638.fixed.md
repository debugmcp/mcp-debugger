**Step and continue failures report the reason and the state together** — a `step_over`/`step_into`/`step_out`/`continue_execution` that could not run (say, the program was not paused) returned `{success: false, error: "Not paused"}` with no `state`, because the server facade threw the result away as an `Error` and only the message string survived; `continue_execution` additionally collapsed its result to a boolean, leaving its handler's failure message as dead code. The facade now returns the controller's verdict as data — matching `pause_execution`, which always did this — so failure envelopes carry `error` and `state`, and a successful `continue_execution` now reports `state` too (honestly `"paused"` when a breakpoint fired before the acknowledgement resolved).
