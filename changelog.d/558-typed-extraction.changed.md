**Adapter policies report which scope supplied the locals they extracted** — `AdapterPolicy.extractLocalVariables` returns `{ variables, scopeRefs }` instead of a bare `Variable[]`, so the session layer no longer rediscovers the contributing scope by comparing variable object identity against every fetched scope. Scope naming and per-scope truncation attribution (#438) now read the refs the policy reports, and a policy can name more than one contributing scope — which is what lets the JavaScript adapter merge block and function scopes for #558. No change to `get_local_variables` output for any existing adapter (#558)
