**A Flutter attach to an iOS simulator by `deviceId` alone is refused up front** — the simulator has no logcat-style discovery of an app another tool started, so `flutter attach -d <udid>` waited for a connection that never came and the attach failed only at the thread-verification deadline; a simulator UDID without `adapterConfig.vmServiceUri` is now refused immediately with the URI hint, as desktop ids are, and the `app.debugPort` URI of the `flutter run --machine` that started the app attaches in ~4 s (measured on an iMac Pro); Android devices keep the no-URI recipe (#1020)
