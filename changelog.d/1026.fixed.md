**A Flutter launch no longer fails once a day on the tool's update banner** — on any box one Flutter stable behind, the Flutter tool printed its "A new version of Flutter is available" box on stdout ahead of the debug adapter's first frame, once per day; the frame decoder cut its header block at the first blank line, which only the real header supplied, so the banner and the `Content-Length` line shared one block, the initialize response was thrown away with the banner, and the launch failed with "Debug proxy initialization did not complete within 30s". The adapter now runs the tool with `--no-version-check --suppress-analytics` ahead of `debug-adapter`, and the shared decoder resyncs on a `Content-Length` found inside a malformed block, so a stray line ahead of any adapter's frame costs nothing (reproduced on demand by setting the tool's version-check stamp back) (#1026)
