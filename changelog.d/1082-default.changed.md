**JavaScript child processes are debugged by default** — a Node launch or attach now sends js-debug `autoAttachChildProcesses: true` unless the caller says otherwise, so every Node process the program starts (`fork()`, `spawn(process.execPath, …)`, a `cluster` worker, a grandchild) is reported and becomes a child debug session: listed with `parentSessionId`, stopping on the parent's breakpoints, reported by the parent's `wait_for_stop` with `sessionId` naming it. Each child counts against `DEBUG_MCP_MAX_CHILD_SESSIONS` (default 32); beyond the cap a fork is released by a throwaway attach to run undebugged, never parked (#501's wedge, which the old attach default of `false` guarded against, cannot happen). Opt out per launch with `dapLaunchArgs: { autoAttachChildProcesses: false }`, per attach with `adapterConfig: { autoAttachChildProcesses: false }` (the children then run untouched, as before), or server-wide with `DEBUG_MCP_MAX_CHILD_SESSIONS=0`. A launch child's output is on the launch session's buffer (`get_output` answers `outputOn`); an attach root's children keep their own console output (#1005, #1082).
