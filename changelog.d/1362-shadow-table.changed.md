**Session state transitions are checked against a table, in shadow mode** — every write of a session's state now names the event behind it, and a check beside the existing code compares the transition with a table (`src/session/machine/transition-table.ts`). Nothing is refused and no answer changes: a transition the table does not list, or one whose guard is not met, is one `[state-shadow]` line at `warn` in the server log and a counter. `MCP_STATE_SHADOW=off` turns the check off, `MCP_STATE_SHADOW_LOG=<directory>` writes every verdict there as ndjson for a diagnosis, and the unit suite runs it in `strict`, where an unlisted transition fails the test. First stage of the session state machine (#1362).
