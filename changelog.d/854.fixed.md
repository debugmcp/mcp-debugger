**The dev proxy no longer cuts backend tool calls off at 60 seconds** — it forwarded every call with the MCP SDK client's default request options, so a call that is slow by design (`evaluate_expression` or `redefine_classes` with a `timeout` up to 600 s, `wait_for_stop`) failed at 60 s with `MCP error -32001: Request timed out` and a hint that the backend "did not settle", which describes a restart in flight rather than a backend busy answering. Backend calls now get a ceiling above the longest a tool may take and carry the caller's cancellation signal, so a call the client gave up on stops in the backend too; a request timeout from a running backend is reported as a call that was not answered. Development-only: the proxy is not part of the shipped server (#854)
