# COBOL Debugging Examples

Example programs for debugging GnuCOBOL with mcp-debugger's COBOL adapter (CodeLLDB behind the COBOL DAP shim). Fixed-format sources; each prints a `COBOL_DEBUG_MARKER:` line the e2e tests look for.

## Prerequisites

- GnuCOBOL 3.1.2+ (`cobc`) — the adapter compiles these on launch:
  - **Ubuntu/Debian**: `sudo apt install gnucobol3`
  - **macOS**: `brew install gnucobol`
  - **Windows**: MSYS2, then `pacman -S mingw-w64-x86_64-gnucobol` (set `COBC_PATH` if `cobc.exe` is not on PATH)
- CodeLLDB is vendored; nothing else to install.

The adapter compiles with `cobc -x -g -fdump=ALL --save-temps -t <lst> -ftsymbols -A "-O0 -gdwarf-4"` into `.debug-mcp/cobol/<name>/<buildKey>/` next to the source. Build one yourself the same way if you want a prebuilt target (`-gdwarf-4` matters on MinGW).

## Example Programs

Paths below are repo-relative for readability; real calls need absolute paths.

1. **hello.cob** — one of every storage type: DISPLAY numerics, `COMP`, `COMP-3`, `COMP-5`, `COMP-2`, a group with 88-levels, `OCCURS 5`, `OCCURS … DEPENDING ON`, `REDEFINES`.
   - Break at **line 32** (`PERFORM 1000-INIT`, the first PROCEDURE statement): every VALUE is initialised, so `get_local_variables` shows the whole WORKING-STORAGE (`WS-SCALED = -123.45`, `WS-BINARY = -123456789`, `WS-STATUS-ACTIVE = true`, …).
   - Break at **line 46** (`ADD WS-SCALED TO WS-TOTAL`): `WS-TOTAL` is `1500.00` here; `step_over` makes it `1376.55`. `evaluate_expression` targets: `WS-AMOUNT(3)`, `WS-ID OF WS-GROUP`, `WS-NAME(1:5)`, `WS-PACKED /hex`.

2. **calls/main.cob** + **calls/sub.cob** — a static `CALL "CALLSUB" USING WS-ARG-REC`; the callee has LOCAL-STORAGE and LINKAGE.
   - Launch `main.cob` with `dapLaunchArgs: {"sources": ["calls/sub.cob"]}`.
   - Break at **sub.cob line 16** (`MOVE LS-WORK TO LK-SUM`): scopes are `LOCAL-STORAGE` (`LS-WORK = 1234`) and `LINKAGE` (`LK-SUM` still `0`). `step_out` returns to main.cob line 14, the statement after the CALL.

3. **copybook/main.cob** + **wsrec.cpy** + **procpara.cpy** — a WORKING-STORAGE record and a whole paragraph pulled in by `COPY`.
   - Launch with `dapLaunchArgs: {"copybookDirs": ["copybook"]}` (cobc runs in the artifact directory, so the copybook directory must be named).
   - Break at **procpara.cpy line 2** (`COMPUTE CP-PRICE = CP-PRICE * CP-QTY`): the stop reports the `.cpy` file as its source; `CP-PRICE` goes from `19.99` to `239.88`.

4. **dyn/main.cob** + **dyn/mod1.cob** — a dynamic `CALL WS-MOD-NAME` into a separately built module.
   - Launch `main.cob` with `dapLaunchArgs: {"modules": ["dyn/mod1.cob"]}`; the module is built with `cobc -m` and put on `COB_LIBRARY_PATH`.
   - A breakpoint at **mod1.cob line 8** (`ADD 1 TO LK-VALUE`) stays `verified: false` until the module loads, then verifies and hits. `WS-VALUE` is `41` before, `42` after.

5. **rterror.cob** — subscript 5 of a 3-element table (the SSRANGE case).
   - Launch with `dapLaunchArgs: {"runtimeChecks": true}`; the default `breakOnExceptions: "uncaught"` (`cobol_runtime_error`) pauses at **line 13** (`ADD WS-CELL(WS-IDX) TO WS-SUM`) before libcob aborts. `continue_execution` lets libcob print its `subscript of … out of bounds` message and exit 1. Without `runtimeChecks` there is no check to trip.

6. **s0c7.cob** — `"ABCDE"` redefined as `PIC S9(9) COMP-3`, then added (the S0C7 case).
   - `WS-PACKED` shows `<invalid packed: 0x4142434445>`; with `runtimeChecks: true` the `ADD` at line 11 pauses on the `not numeric` runtime error.

7. **sysin.cob** — `ACCEPT WS-LINE FROM SYSIN`.
   - Launch with `dapLaunchArgs: {"stdinFile": "<a text file>"}`; break at line 9 to see `WS-LINE` filled. Without `stdinFile` the ACCEPT reads empty on Windows and blocks on Linux.

8. **pause.cob** — a 300-second loop of `CALL "C$SLEEP"` for `pause_execution` and attach-by-PID.

   **To debug (attach):**
   ```bash
   # 1. Source-launch pause.cob once through the adapter (start_debugging, then close_debug_session):
   #    it builds examples/cobol/.debug-mcp/cobol/pause/<buildKey>/pause[.exe] plus pause.cobol-symbols.json.
   # 2. Run that executable in the background:
   examples/cobol/.debug-mcp/cobol/pause/<buildKey>/pause &
   # 3. attach_to_process with the PID and adapterConfig {"manifestDirs": ["<that <buildKey> directory>"]}
   ```

## Debug Configurations

- Launch a source: `start_debugging` with `scriptPath` = the `.cob` file; options (`dialect`, `format`, `copybookDirs`, `sources`, `modules`, `runtimeChecks`, `stdinFile`, `cobcFlags`, `forceRebuild`, `engineScopes`) go in `dapLaunchArgs` as written above, or equivalently in `adapterLaunchConfig` (the smoke tests use that key; it wins when both name an option).
- Launch a prebuilt executable: `scriptPath` = the binary (built with `cobc -g`), plus `dapLaunchArgs: {"sources": [...]}` so the symbol manifest is regenerated by a translate-only `cobc -C`; without a manifest only the engine's C view of variables is available.
- Attach: `attach_to_process` with `processId` and `adapterConfig: {"manifestDirs": [...]}`. On Linux, `kernel.yama.ptrace_scope=1` blocks attaching to non-child processes.
- Mainframe-shaped programs: `dapLaunchArgs: {"dialect": "ibm", "format": "fixed", "copybookDirs": [...], "runtimeChecks": true, "stdinFile": "..."}` — see [docs/cobol/README.md](../../docs/cobol/README.md#mainframe-migration-recipe).

## Running Tests

```bash
pnpm vitest run tests/e2e/mcp-server-smoke-cobol.test.ts --project e2e   # host: needs cobc; self-skips without it
pnpm vitest run tests/e2e/docker/docker-smoke-cobol.test.ts               # Docker lane (build the image first: npm run test:e2e:container runs every docker test)
```

The decoder and manifest-parser unit tests (fixtures captured from GnuCOBOL 3.1.2 and 3.2 on Linux and Windows) run with `pnpm --filter @debugmcp/adapter-cobol test`.
