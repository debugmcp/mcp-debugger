## [Unreleased]

## [0.25.1] - 2026-09-30

### Added
- **Listed in the official MCP Registry as `io.github.debugmcp/mcp-debugger`** — the repository carries a `server.json` naming the npm package (run with `npx`, stdio) and the Docker image (stdio, with the project mounted at `/workspace`). The CLI package declares `mcpName` and the image carries the `io.modelcontextprotocol.server.name` label, which the registry checks before it accepts a version. Each release publishes the listing after npm and Docker, logging in with GitHub Actions OIDC, so no secret is stored; prerelease tags are skipped (#835)

### Security
- **npm packages publish with no stored token** — every `@debugmcp/*` package now publishes through npm trusted publishing (OIDC) from the release workflow, so CI holds no npm or PyPI token; the `NPM_TOKEN` path is gone from `release.yml` (#837)

## [0.25.0] - 2026-09-29

### Highlights
- **Rust and C/C++ debugging work out of the box everywhere npm installs** — CodeLLDB now ships as five per-platform packages (`@debugmcp/codelldb-*`) that npm installs as optional dependencies, and the CLI tarball shrinks from about 54 MB to a few MB (#383)
- **COBOL debugging, the ninth language** — GnuCOBOL programs debug with COBOL-shaped variables, PERFORM-aware stepping, paragraph and section breakpoints, and attach by PID (#759)
- **`mcp-debugger doctor`** — one command reports every language's runtime and debugger toolchain, with install hints (#423)
- **Kubernetes debugging recipe** — port-forward and ephemeral-sidecar examples, registry-free manifests and per-language attach presets, verified weekly on kind (#424, #451)
- **The HTTP transport is locked down by default** — it binds `127.0.0.1` and validates `Host` and `Origin`; `--bind` and `--allowed-host` open it deliberately for containers and remote clients (#667, #671, #677, #680)
- **Launches say how they ended** — a launch that runs to completion names its exit code and the breakpoints that never hit, and a launch with nothing armed to stop it answers `pending` after 5 s instead of waiting out the 30 s ceiling (#701, #815)
- **Exit codes for Go and for JavaScript in Docker** (#753, #796)
- **Breakpoint records match what the debugger said** — a refused re-send leaves the adapter's own answer on the breakpoints, JavaScript breakpoints that fired are reported bound, and breakpoints can be set between runs for `restart_debugging` (#754, #673, #806)
- **JavaScript launches honour their options** — `adapterLaunchConfig` keys pass through with feedback on what was used, `stopOnEntry` and environment removals work, and compiled TypeScript stops in its source view (#684, #703, #709, #791, #792)
- **Lighter startup** — transports and adapters load lazily and the startup reapers are bounded: a freshly started stdio server drops from 287 MB to 190 MB (#395, #407–#411)
- **pi package** — `pi install npm:@debugmcp/mcp-debugger` registers the server and the debugging skill (#714)
- **Signed everywhere** — the Docker image and the PyPI launcher now carry build attestations, like the npm tarballs (#430)

### Added
- **COBOL debugging (GnuCOBOL + CodeLLDB)** — a new `@debugmcp/adapter-cobol` (language id `cobol`, bundled in `@debugmcp/mcp-debugger` and preloaded in the Docker image, which now installs `gnucobol3`). Launch a `.cob`/`.cbl` source (auto-compiled with `cobc -g -fdump=ALL -A "-O0 -gdwarf-4"` into `.debug-mcp/cobol/`, with `dialect`, `format`, `copybookDirs`, `cobcFlags`, `runtimeChecks` and `stdinFile` launch options) or a prebuilt executable (its symbol manifest is regenerated from `sources` by a translate-only `cobc -C`). A Node DAP shim between mcp-debugger and the vendored CodeLLDB engine turns the compiler's own dump-routine metadata into COBOL-shaped debugging: `WORKING-STORAGE` / `LOCAL-STORAGE` / `LINKAGE` scopes with DISPLAY, COMP, COMP-3, COMP-5, COMP-1/2, group, OCCURS (including DEPENDING ON), REDEFINES and 88-level items decoded to their COBOL values (invalid packed data is shown as `<invalid packed: 0x…>` rather than crashing), `evaluate_expression` on data-names with `OF`/`IN` qualification, subscripts and reference modification, breakpoints in copybooks, statement-granular `step_over`/`step_into`/`step_out` (the engine alone stops on every generated-C line), and a `cobol_runtime_error` exception filter that pauses on libcob runtime errors (subscript out of bounds, non-numeric data — the S0C7/SSRANGE analogues) before the abort. Milestone M2 adds attach by PID with the manifest regenerated from `sources` (the process is not touched), data-division scopes served from the nearest COBOL frame when a job is paused inside libcob, `runner: "cobcrun"` to run module-only builds under GnuCOBOL's module loader, and `-m` modules named after their PROGRAM-ID so a dynamic `CALL` resolves them on Linux. Milestone M3 adds COBOL-shaped control flow: `step_over` on an out-of-line `PERFORM` runs the performed range (loops included) and stops on the statement after it, `step_out` inside a performed paragraph returns to the statement after the PERFORM that entered it, `set_breakpoint {function: "1000-INIT"}` binds paragraph, section and PROGRAM-ID names (qualifiable as `1000-INIT OF PAYROLL`), logpoints interpolate `{WS-NAME}` COBOL data references without pausing, and `get_stack_trace` lists the active PERFORMs as frames under the program (`HELLO: 0000-MAIN (PERFORM 1000-INIT)`). Verified against GnuCOBOL 3.2 (Windows MSYS2, Ubuntu 26.04) and 3.1.2 (Ubuntu 24.04) (#759)
- **The npm package is a pi coding-agent package and ships the agent skill** — `@debugmcp/mcp-debugger` now carries `skills/debugging/` and a `pi` manifest (the skill directory plus a `pi-mcp-adapter` server entry in `pi.mcp.json`), so `pi install npm:@debugmcp/mcp-debugger` registers the server and the skill with no clone; the skill is also reachable at `node_modules/@debugmcp/mcp-debugger/skills/debugging` for any harness that can point at a skills directory. Thanks @pikujs for the package (#714)
- **`start_debugging` says how a launch that ended before reporting a pause ended** — such a launch answered a bare `state: "stopped"`, and nothing in the response said the debuggee had exited, with what code, or that its breakpoints — verified ones included — were never hit; the #467 warning only names breakpoints that never bound. The message now says whether the program ran to completion (exit code 0), exited with a non-zero code, or ended without reporting one; `data.exitCode` carries the code when the debuggee reported it; `data.unhitBreakpoints` lists every line breakpoint the program ran past (`file`, `line` as bound, `requestedLine` when the adapter moved it, `verified`; logpoints the adapter supports are left out), and verified line and function breakpoints that were never hit are named in the sentence. A stop that arrived in the same tick as the exit is named instead of a list that would misreport it. `restart_debugging` returns the same fields (#701)
- **`--bind <address>` / `MCP_HTTP_BIND` choose the interface the `http` and `sse` transports listen on, and `/health` reports it** — precedence is the flag, then the variable, then `127.0.0.1`. `localhost` is normalized to `127.0.0.1` (Node would bind only the first resolved address family and refuse `127.0.0.1` clients); only IP literals are accepted, and an unusable value refuses to start by name, like `--allowed-host`. An empty value is refused too — unlike an empty `MCP_HTTP_ALLOWED_HOSTS` — because a silent loopback fallback inside the image would leave the published port unreachable with nothing saying why. A non-loopback bind logs a warning naming the knob that set it, the fact that the Host/Origin allowlist stops browsers rather than direct clients, and the `--allowed-host` entry clients dialing that address will need; the image's own `MCP_HTTP_BIND=0.0.0.0` (under `MCP_CONTAINER=true`) is reported at info level instead, since the published port or port-forward is the access control there. A failed `listen()` names the address, the port and the knob (`EADDRNOTAVAIL`, `EACCES`, `EADDRINUSE`). The startup line prints a URL a client on the machine can open. `GET /health` gains `listening: { address, port }`, taken from the bound socket. The PyPI launcher forwards `--bind` to the npx-run server too (it used to warn that the flag was Docker-only) and says when the flag is ignored for `stdio` (#680)
- **`http` mode gains an explicit Host allowlist: `--allowed-host <host>` (repeatable) and `MCP_HTTP_ALLOWED_HOSTS` (comma-separated)** — the Streamable HTTP endpoint accepts only loopback `Host` headers (`localhost`, `127.0.0.1`, `[::1]`) as DNS-rebinding protection, which is the right default for a tool that spawns processes and attaches to PIDs, but there was no configuration path at all: a server in a container reached by its service name (`http://mcp-debugger:3001/mcp`) answered 403 with no way to say "another access control fronts this". Operators can now extend the allowlist explicitly. The loopback default is unchanged, there is no wildcard, an unusable entry (a URL, a bare IPv6 literal, `*`) refuses to start by name instead of being dropped, and the effective allowlist is logged at startup. Thanks @v8eta for the bundle-level analysis (#667)
- Expose a bounded, sanitized `debug://sessions/{id}/proxy-log` MCP resource for every session launch attempt and include its URI beside `proxyLogPath` in failure diagnostics (#571)

### Changed
- **Bumped `dotenv` 16 → 18 in the JavaScript adapter** — the adapter uses only `parse()`, to read `envFile`, and dotenv 18's default parser is unchanged, so `.env` files load exactly as before. `dotenv` is bundled into the `@debugmcp/mcp-debugger` CLI; the standalone `@debugmcp/adapter-javascript` package now depends on `dotenv` ^18 (#803)
- **A JavaScript launch forwards the `adapterLaunchConfig` keys it does not derive itself** — the launch transform used to emit a fixed set of keys, so js-debug options such as `trace`, `perScriptSourcemaps`, `timeouts` or `sourceMapPathOverrides` passed through `adapterLaunchConfig` were silently dropped (attach has forwarded unrecognised keys since #466). They now reach js-debug as-is and the forwarded names are logged. Keys the transform derives (`env`, `skipFiles`, `smartStep`, `outFiles`, the runtime selection, the source-map settings) keep winning; `autoAttachChildProcesses` follows an explicit caller boolean as it does on attach; a caller `resolveSourceMapLocations` — an array of globs or an explicit `null` — wins over the launch default on both launch and attach, and any other value is replaced by the default with a warning instead of crashing js-debug. The pwa-node shape mcp-debugger owns (`type`, `request`, `name`, `console`, `outputCapture`) and the two keys that break a parent launch (`__pendingTargetId`, `attachSimplePort`) are dropped with a warning (#703)
- **`IDapClient` now describes its implementations** — `on`/`off`/`once`/`removeAllListeners` return `this` (every implementation is an `EventEmitter`) and `sendRequest` is typed to `DebugProtocol.Response` like `MinimalDapClient`, so the production factory no longer needs an `as any` and test doubles are checked against the interface instead of widened past it. The app-local duplicates of the shared external-dependency interfaces (`src/interfaces/external-dependencies.ts`, and the `IProcess*` copies in `src/interfaces/process-interfaces.ts`) are gone — `@debugmcp/shared` is the single declaration. `@debugmcp/shared`'s placeholder `IProxyManager`/`IProxyManagerFactory` are marked `@deprecated` — the real interfaces live in the app and nothing in this repo imports the placeholders any more (#691, #692)
- **The `http` and `sse` transports bind `127.0.0.1` by default instead of every interface** — the Host/Origin allowlist (#667) stops browsers, not a LAN client that sends `Host: localhost` itself, so an unauthenticated debugger on a bare host was reachable from the network. A client on another machine now needs `--bind 0.0.0.0` (or `MCP_HTTP_BIND=0.0.0.0`) plus `--allowed-host <name>` for the name it uses — or a tunnel / port-forward, as before. The Docker image sets `MCP_HTTP_BIND=0.0.0.0`, so published ports (`-p 127.0.0.1:3001:3001`, `kubectl port-forward`) keep working unchanged (#680)
- **A caller-supplied `skipFiles` on a JavaScript launch replaces the default list instead of being merged into it** — the adapter used to add `<node_internals>/**` and `**/node_modules/**` to whatever `skipFiles` the caller passed, so a caller could only ever skip more. It now follows VS Code's launch.json semantics: the list you pass is the list js-debug gets, and the defaults apply only when you pass none. A launch that relied on the merge should add the two default patterns to its own list (#678)
- **Documentation corrected against the code for this release** — the structural refactor refreshed
6 of 16 architecture docs and several guides had not been touched since March, so the tree had
accumulated instructions that could not work: an `api-reference` documenting a `StartDebuggingParams`
object form of `startDebugging` (it is positional) and a `terminate()` that was never written, a
`debugging-guide` telling you to extend a `registerTools()` method and a `CallToolRequestSchema`
switch that no longer exist, a `testing-guide` naming an `npm run test:ui` script that is not there,
and `examples/rust`/`examples/go` inventing CLI subcommands. Two capability claims were wrong in
public: `set_breakpoint`'s schema omitted C/C++ from its function-breakpoint and logpoint language
lists although the adapter supports both, and the README's remote-attach list omitted JavaScript,
whose host/port attach is verified weekly in CI. Path semantics were documented backwards in two
places -- host mode rejects a relative path, container mode rejects nothing and re-roots everything
under `MCP_WORKSPACE_ROOT`. `mcp-debugger doctor` now appears in the two docs a new user opens, the
`http` transport finally has a config example, and the per-session log layout, the `proxy-log`
resource and ~17 environment variables are documented. Four docs whose wrong parts were inventions
rather than stale details are archived with a header explaining why. A new `pnpm run check:docs`
gate runs in CI so relative links that stop resolving, and tool/language counts that fall behind the
code, fail the build instead of drifting (#635, #643)
- **The changelog gate now covers the root `package.json`, and judges every manifest by what it
ships** — the gate picked its candidates by path prefix (`src/`, `packages/`, `tools/`), and the
root manifest starts with none of them, so it was never examined at all. Its `dependencies` and
`optionalDependencies` are exactly what `dist/index.js` and the Docker image run: registering the
C/C++ adapter in `optionalDependencies` shipped a whole language and the gate said nothing. The
root manifest is now a gated path, and every manifest — root and package alike — is judged
against one list of shipping-surface keys (`dependencies`, `optionalDependencies`,
`peerDependencies`, `bin`, `main`, `exports`, `files`, `engines`, `type`) rather than the
"anything but `devDependencies`" rule of #629. That rule could not be reused as-is: the root
manifest carries 104 npm scripts, and over 130 root-manifest commits it would have demanded a
fragment for 115 of them versus 40 under the allowlist. `version` and `scripts` no longer gate
anywhere — a release PR bumps `version` across every manifest, and the changelog entry for a
release is the collated section itself, so requiring a fragment for the bump that cuts the
release was circular. `pnpm-lock.yaml` is deliberately still not gated: every dependency PR
touches it, devDependency-only ones included, so gating on it would undo #629 (#630)
- Stack traces, local-variable discovery, and default expression evaluation now
share one injected `FrameAnchorResolver`; an explicit evaluation `frameId`
remains authoritative (#594)
- **`attach_to_process` reports an invalid `verifyTimeout` in the same words every other timeout override uses** — the message changes from `'verifyTimeout' must be a positive number of milliseconds, got: X` to `Invalid 'verifyTimeout': must be a positive number of milliseconds (got X)`, and the clamp warning gains matching quoting. The validation itself is unchanged (positive, finite, clamped to the 10-minute maximum); it now runs through the same helper as the per-request `timeout` argument on `evaluate_expression` and friends, rather than a hand-written copy of the same rules (#592)
- **Launch failures are torn down the way attach failures are, and both report instead of throwing when the session is closed mid-teardown** — when `start_debugging` fails after the proxy exists, the proxy's listeners are removed before it is stopped, the session's mirror record is cleared with the worker that hosted it, and a `stop()` that fails is logged instead of turning the reported failure into a rejection (attach already did all of this). If `close_debug_session` lands while that teardown is running, `start_debugging` and `attach_to_process` now return `{ success: false, state: "stopped" }` with the error and diagnostics instead of rejecting with `SessionNotFoundError`. A failed attach verification (no threads reported, or the adapter died) goes through the same teardown, so `lastProxyPid` is recorded for the leaked-worker check. A relaunch or re-attach always awaits a previous worker's in-flight stop before starting — it used to skip that wait whenever a terminal event had already cleared the proxy handle, racing the old worker's exit. The attach `threads` poll passes its remaining verification window to the worker as the request timeout, so an abandoned poll is cancelled end-to-end instead of stalling the teardown for the full drain window (the timeout quoted in the verification error now renders in whole seconds, and a worker that is alive but never answers can extend verification by up to the parent-side request margin of 5 s beyond `verifyTimeout`). A dry run that never reports back returns the same `data.proxyLogPath` a thrown launch failure returns and writes the same full failure record to the server log; its `Dry run timed out after Nms` message is unchanged. The `Entering startProxyManager` server-log line is now `Entering ProxyLauncher.start`; a failed attach verification tears down through the same path as every other failure, so its server-log lines are the core's `… for session …` messages instead of the former `… for failed attach` pair (#582)
- **The test-typing ratchet gains `--allow-improvement`, and says how to repair a baseline it cannot read** — a dependency bump that makes the test suite type-*cleaner* (a better `@types` package, say) used to fail its own CI check: the ratchet fails on a decrease so the recorded baseline cannot silently go stale, and Dependabot has no way to commit the refresh. CI now passes `--allow-improvement` for PRs authored by `dependabot[bot]` only, which warns on a decrease and still fails on any increase or newly erroring file; pre-push and human PRs stay strict, and the flag is refused alongside `--update`. The trade-off is deliberate and now loud: such a PR can auto-merge leaving `tests/typecheck-baseline.json` stale on main (auto-merge pushes with `GITHUB_TOKEN`, which suppresses push CI), so the run prints a `::warning` annotation on the baseline file and a job-summary line naming the remedy — the next human PR refreshes it with `pnpm run typecheck:tests:update`. Separately, all four "this baseline is unreadable" errors (invalid JSON, wrong shape, a bad per-file count, a path outside the test trees) now name the remedy the fourth already did — delete `tests/typecheck-baseline.json`, then re-record it — because `--update` reads the baseline before writing one, so a corrupt file blocks its own repair (#581)
- Centralize session run-directory, proxy-log, adapter-log, and DAP-trace naming so launch, diagnostics, and stale-log cleanup share one exact layout contract (#572)
- Persist structured proxy-failure diagnostics for mid-session adapter/proxy deaths and expose them on errored `list_debug_sessions` entries and failed or empty `get_stack_trace` responses (#570)
- Bound proxy-failure log reads to the final 64 KiB before redacting and trimming them to 80 lines, and remove redundant raw-error serialization from diagnostic log metadata (#569)
- **One wording for a missing `sessionId`** — the 15 tools that reject a missing
`sessionId` up front used two different messages depending on which one you
called: `Missing required sessionId` from `close_debug_session`,
`attach_to_process`, `detach_from_process`, `step_over`/`step_into`/`step_out`,
`continue_execution`, `list_threads`, `get_stack_trace`, `expose_session` and
`unexpose_session`, and `Missing required parameter: sessionId` from
`list_breakpoints`, `remove_breakpoint`, `clear_breakpoints` and
`restart_debugging`. All 15 now say `Missing required parameter: sessionId`, so
11 of them changed text. Tools that take several required parameters keep their
own `Missing required parameters` message, and the tools that never checked up
front are unchanged (#568)
- **Adapter policy objects now publish their concrete types** — every `AdapterPolicy` export in
`@debugmcp/shared` was declared with a type annotation (`export const GoAdapterPolicy:
AdapterPolicy = {…}`), which widened the object literal to the interface. Consumers therefore saw
every optional member as possibly-`undefined` even when the policy plainly implements it, and saw
each method's declared arity rather than its real one. The exports now use `satisfies`, so
conformance is still checked but the concrete shape survives into the published declarations.
`getPolicyForLanguage()` still returns the widened `AdapterPolicy`, so code written against the
interface is unaffected. **Source-breaking for code that uses a policy constant directly**: an
optional member a given policy does not implement is now absent from its emitted type rather than
present-and-optional, so `CppAdapterPolicy.annotateOutputEvent?.(…)` no longer compiles (test for
it with `'annotateOutputEvent' in CppAdapterPolicy`), and a call must match the implementation's
real arity — `GoAdapterPolicy.buildChildStartArgs()` rather than `buildChildStartArgs(id, cfg)`
(issue #562).
- **Adapter policies report which scope supplied the locals they extracted** — `AdapterPolicy.extractLocalVariables` returns `{ variables, scopeRefs }` instead of a bare `Variable[]`, so the session layer no longer rediscovers the contributing scope by comparing variable object identity against every fetched scope. Scope naming and per-scope truncation attribution (#438) now read the refs the policy reports, and a policy can name more than one contributing scope — which is what lets the JavaScript adapter merge block and function scopes for #558. The documented contract also drops a rule that was never true: `includeSpecial: true` returns a superset of `false` only when both calls selected the same scopes, because a policy may legitimately land on a different scope when its anchor scope is empty after filtering (#548). No change to `get_local_variables` output for any adapter other than JavaScript (#558)
- **Attach verification window default raised 5s → 20s** — the `attach_to_process` thread-poll deadline only ever bites when the debug adapter is alive but the target is slow to become debuggable (js-debug child-session adoption on a loaded host, a warming JVM); adapter death still fails fast via the proxy-gone latch, and the poll returns the moment threads appear, so healthy attaches never pay for the headroom. A false "attach failed" on a healthy target is strictly worse for an agent than a slower genuine failure. Pass a small `verifyTimeout` for fast failure-by-design probes (#398)

The proxy now hands the child's authoritative `setBreakpoints` response back through the sync path (marked child-sourced, bounded 3s wait), `attach_to_process` gains the post-launch belt-and-braces re-sync (with a clear+re-set to force a fresh echo for already-registered sets), and every previously-silent mirror failure mode logs. ### Security
- **The `http` endpoint now validates `Origin`, so a web page cannot drive a local debugger from the user's browser** — the Host check (DNS-rebinding protection) was the only guard, and CORS answered every origin with `Access-Control-Allow-Origin: *`, so `fetch('http://localhost:3001/mcp')` from any site passed the Host check and could initialize a session and call every tool. - **Release attestation extended to the Docker image and PyPI launcher** — the docker image publishes a signed provenance attestation and the PyPI launcher ships PEP 740 attestations, alongside the existing npm sigstore provenance and SBOMs (#430)

- **Statement anchors: content-addressed breakpoints** — `set_breakpoint` accepts `statement: "<exact line text>"` instead of `line`: whole-line trimmed-equality matching (the Edit-tool `old_string` skill agents already practice, instead of line arithmetic they're demonstrably bad at). The new `DEBUG_MCP_BP_ADDRESSING` env flag (`line` | `assert` | `content`, default `content`) restricts addressing features — runtime behavior, tool schema, server instructions, and prompt text all gate together, enabling controlled A/B comparisons of agent debugging behavior (#271)

Implemented uniformly as terminate+relaunch (the DAP-spec-blessed emulation — no adapter advertises native restart), so all launch-mode languages work identically; runs while running, paused, or after the program exited. The response's `data.outputReset: true` signals that each launch starts a fresh output buffer — read `get_output` from `since: 0`. Attach sessions and never-launched (or dry-run-only) sessions are refused with clear errors (fixes #238)

Support is gated per adapter: Python/JavaScript/Go/Rust/mock work; Java/.NET fail fast with a clear error; unknown support (Ruby) is accepted with a warning and re-checked against the adapter's live capabilities at launch. The mock adapter simulates logpoints (logs without stopping) for hermetic e2e coverage (fixes #235)

- **Breakpoint management tools** — new `list_breakpoints` (per-session listing with verified state and adapter-assigned ids, optional file filter), `remove_breakpoint` (by breakpoint id, or by file+line which removes every breakpoint at that location), and `clear_breakpoints` (whole session or one file). Removal and clearing take effect immediately while the debuggee is running or paused (the file's remaining set is re-sent, DAP replace-all) and deliberately keep working after the program exits so breakpoints can be adjusted between launches. DAP `breakpoint` events — previously dropped — are now wired end-to-end, so deferred verifications (debugpy module load, JDI class load, js-debug async binding, netcoredbg pending breakpoints) update the stored state; pre-launch breakpoints are also re-synced once a launch completes so their verified state and adapter ids reach the store on adapters that don't push events (fixes #236)

- **`exceptionInfo` enrichment on exception stops** — when a session pauses with reason `exception` and the adapter supports the DAP `exceptionInfo` request, `lastStop.exceptionInfo` is populated best-effort with `exceptionId`, `breakMode`, and details (message, type names, adapter-side stack trace); surfaced via `list_debug_sessions` and `get_stack_trace`.
